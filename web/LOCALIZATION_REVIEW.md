# 表示言語の管理

0.3.19から、開発時に翻訳を自動更新します。対応は日本語・英語・中国語（簡体字／繁体字）・韓国語・スペイン語・フランス語・ドイツ語・ポルトガル語の9種類です。対象はアプリの操作、設定、エラー、変更履歴、プライバシー・ライセンスの説明と要約です。ポルトガル語はブラジルの用語を基本にしています。

## 開発PCの初回準備

通常のプレビュー、生成済みのアプリ、CIには翻訳モデルは不要です。新しい翻訳を生成する開発PCにはNode.js 22以上と[Ollama](https://docs.ollama.com/)を用意し、Ollamaを起動して次を一度実行します。

```sh
ollama pull gemma4:e4b
```

モデルの重みは約9.6GBで、実行時には別途メモリーが必要です。初回のダウンロード後は端末内で生成します。今回の実行環境はOllama 0.32.6です。モデル名だけで最新版を採用せず、`scripts/i18n/translator.json`のdigestと一致する版に限定します。配布元がモデルを更新してdigestが異なる場合は、訳と変更内容を確認して固定値を更新してください。

生成時に必要なら`127.0.0.1:11439`で専用のOllamaを非表示で起動し、終了時に自分が起動したプロセスを閉じます。既存のローカルサーバーを使う場合は`PALMO_TRANSLATOR_URL`で指定できます。HTTPのループバックアドレスだけを許可し、外部ホスト・認証情報付きURL・リダイレクトを拒否します。自分で起動するサーバーには`OLLAMA_NO_CLOUD=1`を指定します。

## 文言・変更通知の更新

1. JavaScriptの文言は日本語で`tr('保存')`、値を含む場合は `` tr`セーブ ${number}` `` と書きます。静的HTMLの本文・`aria-label`・`title`・`alt`・`placeholder`は自動抽出します。`tr(variable)`や文字列の連結は抽出できないため、原則として使いません。
2. 変更通知は`release-notes.json`へ`version`・`date`・日本語の`changes`を追加・編集します。翻訳の空欄を手で作る必要はありません。同じバージョンの文章の修正・追加・削除・並べ替えも検出します。
3. リポジトリのルートで`npm --prefix web run dev`を実行すると、起動時とファイル変更時に翻訳と配布ページを生成し、`http://127.0.0.1:4173/`で確認できます。表示中のブラウザは自動再読み込みしないため、確認時に再読み込みしてください。
4. 一括生成は`node web/scripts/build-offline.cjs`、翻訳だけなら`npm --prefix web run i18n:sync`です。日本語の変更分・翻訳の欠落だけを8言語へ生成します。原文が変わっていない、手で改善した訳は保持します。
5. 自動生成は下書きです。担当エージェントが日本語原文・実装・画面を照合し、追加・変更した文言を全8翻訳言語で校正します。原文が同じでも処理や表示場所が変わった文言は見直します。特に保存／読み込み／削除／復元、ゲーム内セーブ／ステート、否定、互換性の条件、通信の有無、権利条件を確認してください。変更していない校正済みの訳は維持します。
6. 校正後に `node web/scripts/build-offline.cjs` と `node web/scripts/check-i18n.mjs` を実行し、変更した画面をChromium／WebKitで確認します。校正済みの訳が保持され、変数・単位が一致し、長い訳で操作ボタンや本文が欠けないことを確かめます。
7. 校正の基準コミット、対象文言／変更通知の版、対象言語、修正内容をこの文書に、検証結果と未確認範囲を `RELEASE_VALIDATION.md` に記録します。自動生成だけの訳を完成物としてコミット・push・公開せず、校正と検証を終えてから[通常の公開手順](../deployment/README.md)へ進みます。公開可否はその作業での指示に従います。

開発プレビューに生成途中の訳が表示される場合も、校正完了とは扱いません。CIの翻訳検査は登録漏れ・形式・原文との整合を調べるもので、文意や自然さを校正した証明ではありません。担当エージェントによる校正を、人間の母語話者による確認と区別して記録・報告してください。

モデルがない、応答が不完全、差し込み位置が不一致などの場合は生成に失敗します。全言語の生成・検査が成功するまで翻訳ファイルを書き換えず、並行して原文や訳が変更された場合も停止します。書き込みはファイルごとの置換で、原文のハッシュを最後に更新します。複数ファイル全体が1つのトランザクションになるわけではないため、書き込み中に強制終了した場合は再実行して検査してください。同時起動はロックで防ぎ、終了済みのプロセスのロックは次回に回収します。

`scripts/i18n/state.json`は生成済み原文のハッシュです。手で更新して検査を通すためのファイルではありません。変更された原文、新しい翻訳、変更通知、ハッシュをセットでコミットしてください。

## 翻訳漏れの検査

`npm --prefix web run i18n:check`、`build-offline.cjs --check`、配布検査から同じ検査を実行します。CIと公開処理はモデルを呼ばず、漏れがあれば停止します。pushだけで翻訳や公開を自動実行する方式ではありません。

- `src/`のJavaScriptをAcornで構文解析し、`tr`を通さない日本語、抽出できない動的な文言をファイル・行番号付きで検出します。コメントや正規表現を表示文言とは扱いません。Unicodeエスケープも検査します。
- JavaScriptのHTML文字列や表示用プロパティに直接書かれた英語も検出します。JSON・CSS・SVG内の日本語も登録漏れとして検出します。CSSの案内は翻訳済みの属性などから表示してください。
- 静的ページとService Workerの原文、8言語の辞書、変更通知を照合します。原文の変更後に残った古い訳、未登録キー、空訳、言語・件数の欠落、差し込み位置の不一致、不完全な生成文字列を拒否します。バージョンやページ生成物の不一致も別の公開検査で拒否します。
- 翻訳しない固定値は`exclusions.json`へファイル・完全一致の文字列・理由を記録します。現在は母語で表示する言語名と、別途抽出する静的DOM／Service Worker文言の受け渡しだけです。使われなくなった例外も検出します。

静的解析は任意のデータの流れや文意を理解するものではありません。ライセンス原文、コード例、作者・プロジェクト名、ユーザー入力、第三者資産を翻訳対象にしない境界があります。新しい描画方式や外部ファイルからUI文言を組み立てる場合は、抽出器と検査も追加してください。原文から消えた既存キーは、訳の手修正を不用意に失わないよう自動削除しません。
