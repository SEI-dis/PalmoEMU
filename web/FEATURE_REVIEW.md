iOSのクラウド同期・ファイル共有サーバー・購入・外部ダウンロード機能は移植しません。
ROMパッチは利用者が選んだ2ファイルを端末内のWorkerで処理し、新しいファイルを保存します。
既存ROMやセーブを書き換えず、ダウンロード元への問い合わせも行いません。

## 保存と互換性

- DSVの122バイトの末尾情報、サイズ、形式バージョンを検査し、NDSコアへ渡す前に取り除きます。通常のSAVは変更せず、不正なDSVは既存セーブへ触れる前に拒否します。
- IndexedDBをv4からv5に上げ、別ストアへ5分以上の間隔で変更のあったセーブを最大10世代保持します。直近5世代・復旧ステート5世代は従来どおりです。同じ保存トランザクションと所有者確認を使い、保存失敗時に一部だけ更新しません。
- 新しい履歴も端末内の一括バックアップ・個別書き出し・削除対象です。バックアップ形式の版と既存データのキーは維持します。これはゲーム内のレポート操作の代わりではありません。
- NES/SNES/MDの入力だけに2Pを追加。標準libretroとjgenesisの保存・ステートの構造は変更しません。1人用GB/GBC/GBA/NDSには2Pの空入力を適用しません。
- mGBAの旧0.3.19ステート、64 MiB ROM、旧セーブ、6 MiB拡張セーブと16 MiB拡張RAMを合成ROMで確認しました。CPU速度の初期値は1で、通信中も1を強制。既存の1～5倍速とは別の設定です。

SNES標準のMesen-Sは、初期化前のコールバック登録が失われる既存不具合を修正しました。コアを初期化してから映像・音声・入力コールバックを設定します。jgenesisのSNES/MDでは2Pが既定で未接続のため、Webラッパーでゲームパッドを明示しました。重複するMDボタンの別名はORでまとめ、片方の未押下で押下状態を消さないようにしています。

## 表示・入力・負荷

メニューの方向移動、決定・戻る、押しっぱなしの決定抑制、ゲームへ戻った直後の入力を確認しました。
矢印キーは文字入力やネイティブの選択欄を妨げません。再開直後にメニューの遅延解除でゲーム入力が消える問題を修正しています。

LCD/CRTは3倍、xBRZは4倍までに固定し、選んだときだけGPUを初期化します。
コンテキスト喪失・コンパイル失敗時はピクセル表示へ戻り、フィルター変更と終了時にGPU資源を解放します。
NDSと開発用3DSアダプターの2画面とも解放対象です。3DSアダプターでもGPUフィルターの描画経路を確認しました。公開版の3DS起動は引き続き無効です。画像の4象限で色と上下左右の向きを照合しました。
GPU効果は任意で、全端末で軽くなるという意味ではありません。

狭い画面のパッチ選択欄はラベルと入力欄を縦に配置し、GBA設定の選択欄は既存メニュー部品の表示へ統一しました。320px幅のラベル幅を自動検査し、390px幅の日本語画面を画像でも確認しました。

センサーは手動スライダーでも操作できます。端末の動きは利用者が有効にした場合だけ読み、一時停止中は中立値、終了時はイベント解除とします。値はネット送信しません。

## ライセンスとソース

ManicEMU由来のWebコードはAGPL-3.0-or-laterで変更日を明記し、参照したSwift原文・著作権・AGPL全文を保持します。
MPLのコア変更とGPUドライバーはMPL-2.0のまま公開します。RomPatcher.jsのMIT原文と未改変ソースも同梱します。
xBRZはHyllianの許諾とZenjuのGPLv3+例外を含む原文・COPYINGを保持し、GPLv3第13節のAGPLとの組み合わせ規定に従います。
ゲームや利用者のパッチ・画像そのものに権利を与えるものではありません。

JS/WASMは、配布するC/Rustソースを展開し直して独立ビルドした結果と照合しました。
Cの4コアとRustのjgenesisは対応するJS/WASMが一致しています。Rustのバイト一致は記録した同一ビルドパス・ツールチェーンでの確認です。
原文、変更箇所、ハッシュ、ツールチェーンはSOURCES.json、sources/build-evidence.json、sources/alternate-build-evidence.jsonを参照してください。

## 検証と範囲

- upstream-features: DSV正常・破損・原本維持、v4移行、5+10世代と保存失敗の原子性、センサーの中立化、IPS/BPS/UPSとCRC不一致、不正入力、キーボードとゲームパッドのメニュー操作、GPU色・向き・喪失・解放、同一サイトの静的GETのみ。
- two-player: 自作NES/SNES/MD ROMで各2種類のコアの両ポートと他方の入力分離、同名パッドの割り当て・保存、GBの1Pが2P入力で消えないこと。
- backup / nds-browser: 10世代の追加履歴を含む一括バックアップの往復・保存失敗、DSVを実際に読み込んだNDSの起動とSAVとしての永続化。
- game-preferences / input-controls / runtime-performance / multicore: ゲーム別設定、長押し・連射・巻き戻し、フレーム・音声のタイミング、全代替コアの起動・セーブ・ステートを確認。
- 保存互換性: 0.3.19の標準NES/SNES/MDと新コアでステートを相互に読み込み、jgenesisのGB/GBC/NES/SNES/MDでもステート相互読込とセーブ一致を確認。
- core-upgrade: 0.3.19の配布コアと新コアの旧ステート・セーブ移行を合成ROMで確認。

ChromiumとPC版WebKitの自動検査であり、実機iPhoneの傾き・ジャイロや物理パッドの全機種確認ではありません。
各機種の合成ROMによるポート検査であり、全タイトルのマルチプレイを網羅していません。
対応ソース・配布一覧・全文ライセンスの整合性検査と、同じmainコミットのCI成功を公開条件にします。


## 0.3.22の追加機能

2026-10-13。PokemonStartを対象ゲーム、pm-start/mGBA_celio_editionを互換性の基準とし、ManicEMUの操作とmgba-celio-webのWeb実装を参考に追加しています。上の0.3.20とは別に、追加機能の動作検証・対応ソースの独立再ビルドを行いました。検査の範囲はRELEASE_VALIDATION.mdに記録しています。

### 変更内容

- DS：両コアの公開libretro設定を使用した5秒の疑似息入力と、起動前の本体言語選択。コア側の疑似音源を利用し、録音しません。ManicEMUのsimBlowingを参考にし、メニューの既存部品を使用します。設定キーはndsLanguage、既定値defaultで従来の初期言語を維持。通常resetでは本体言語を作り直しません。
- GB/GBC：既存mGBAの回転センサーAPIへの設定入口を追加。GBA固有の太陽・CPU・ジャイロは表示しません。端末センサーの明示的な許可、一時停止時の中立化、終了時の解除を維持します。
- ZIP：標準ブラウザAPIでBlobを部分読み込みし、展開上限・CRC・重複区間を検査。順次保存し、重複ROMのIDは従来のSHA-256と同じです。NDSのBlob化は重複判定後だけ行います。途中追加の件数をエラー時にも表示。保存済みROM・セーブ・設定の識別子や保存形式は変更しません。
- 映像：Celio WebのchoosePixelTransfer/drawFrameをもとに、行単位／Cのpacked転送を合成入力で比較。利用者ROMの読み込み前だけ実行し、非表示・粗い時計・不一致・例外では行単位へ戻します。計測時間を制限し、選択後のフレームごとの計測は行いません。LCD/CRTの強度は0〜1、初期値0.5で従来の見た目を維持。
- 時計：mGBA標準のRTC_WALLCLOCK_OFFSETを使用。初期値はRTC_NO_OVERRIDE、整数秒・最大10年で入力制限。ゲーム別設定をステート読込・セーブ読込・再起動後に再適用。RTCの既存保存形式を変更しません。
- 振動：mGBAのmRumbleIntegratorからゲーム由来の出力を受け、利用者が有効にした場合だけ最後に操作した1Pのゲームパッドへ送信。indexとidを照合し、同じ機種の別パッド全部を振動させません。無効化・非表示・一時停止・切断・終了・API拒否時に停止します。タッチ時の振動機能は維持。

DSの2コアとmGBAは、配布ソースを別ディレクトリへ展開して独立にビルドし、JS/WASMの一致を確認しました。RTC初回適用、振動の最初の短いパルス、パッド再接続時の選択解除、ローカル2Pへの時計設定引き継ぎも確認しています。mGBAソースのversion.cmakeは、展開先の親にある無関係なGit履歴を使わないよう修正しました。

### 見送り・調査の限界

- `.pks`：対象外。別のパッチ適用手段で作成した対応形式のROMを使用します。
- PokemonStartのネットのミラクル交換：[v0.41.0の変更履歴](https://github.com/pm-start/PokemonStart/blob/85d507533d4922c0f91822ec78a5a638fa3c7a3f/CHANGELOG.md#pokemonstart-v0410)には追加の記述があります。一方、確認した公開資料には専用通信の接続先・メッセージ仕様・ROMからの起動方法が揃っていません。既存Celio通信と同じとも別とも断定せず、未確認として扱います。実装にはROM側のSIO／メモリ／Lua等の入口、公開されたサーバー仕様、送受信データ範囲、キャンセル／切断時の扱いが必要です。推測した外部接続やROM・セーブのアップロード機能は追加しません。
- USB実機からオンライン部屋への中継：[Celio Webのlink-session.js](https://github.com/pm-start/mgba-celio-web/blob/23235bc6db1b67009808c0dc7e1f25131eb75e7a/web/link-session.js)にありますが、主対象のiPhone SafariではWeb Serialが使えず、手元の実機で通信・保存を確認できないため今回は追加しません。既存のUSB接続は変更しません。ネットのミラクル交換に必要な機能と決めつけません。

### 検証範囲

新規テストに加え、既存セーブ・ステート移行、入力・通信・巻き戻し、多言語・オフライン・更新の回帰検証を行います。DSの疑似マイクは自作プログラムでARM7のSPI標本まで確認し、APIを呼べるだけで対応済みとは扱いません。iPhone実機の操作感・性能、物理ゲームパッドの振動はPCの自動検査に含みません。最終結果、配布内容と同じコミットのCI成功をRELEASE_VALIDATION.mdと公開手順で確認します。

新規のオリジナルWebコードはAGPL-3.0-or-later、mGBAのoptions.hはMPL-2.0。pixel-transfer.jsはCelio Web由来のMPL条件と原著者表示を保持し、この結合作品ではMPL 3.3に基づくAGPLの追加選択肢も示します。既存のAGPL/GPL/MIT等の権利表記は除去しません。今回のROM・ZIP・時計・入力処理による新しいネット送信はありません。

## 0.3.24の追加機能と保存設計

2026-10-13。今回はROM更新からのセーブ引き継ぎ、入力テストとタッチ調整、DSのふた操作、選択復元、ステート個別入出力、ROMのみの取り外し、GB/GBC端末内通信をまとめて追加します。

- ROM更新：旧・新のゲームロックを取得し、元のセーブのハッシュ／日時／選択コアを再確認。新ROM・セーブコピー・更新前の専用退避を単一トランザクションで保存します。追加先のすべてのコア用セーブ・ステート・履歴・セッションを調べ、既存データがあれば拒否します。旧データは変更せず、ステートを移行しません。容量や同一機種という条件はゲームのセーブ互換性の判定ではありません。
- ROM取り外し：ゲームロック取得後にROMストアだけを削除し、ライブラリへ未追加状態を記録。同一ハッシュのファイルを再追加すると、既存の名前・設定・セーブ・ステートを維持して解除します。
- 選択復元：ユーザーが選択したゲームIDだけをロック・置換。現在／バックアップの保存日時を表示し、共通設定は明示選択に限定。元データの退避と復元を一括保存します。
- 個別ステート：PalmoEMU専用エンベロープでROM SHA-256・機種・容量・コア・データハッシュを検証。ゲーム内セーブを含む場合もハッシュ／上限を確認。新しいUUIDの枠へaddし、上書きと自動ロードをしません。他アプリのステート互換を称しません。
- 入力：共通／ゲーム別設定に十字キーの方向数・中央の遊び・斜め感度・タッチ範囲を追加。標準設定は従来値、取り込みスキンの幾何は変更しません。ROMなしの入力テストからタッチ・キー・物理パッドの入力を確認します。
- DS：ManicEMU simLid操作を参考に、DeSmuME 2015のL2トグルとmelonDSのL3状態へ接続します。実際のふた状態を読み、ステート復元後も同期します。
- GB/GBC：mGBAのGBSIOLockstepで同一WASM内の2台を同期し、両方のRAM・セーブ・画面を分離。GBAのCelio経路とは分け、GB/GBCにオンラインやUSBを提示しません。完了は利用者の確認操作で両方のセーブを一括確定し、中止時は開始前へ戻します。

移植・参考元の作者と固定版はNOTICES.mdおよびSOURCES.jsonを維持します。Webの安全なデータ移行・入力調整はAGPL、mGBAブリッジはMPL、DSブリッジはAGPL、DSコアは既存のGPL条件を守り、配布バイナリと対応ソースを一緒に更新します。新しい外部通信やROMアップロード処理は追加しません。詳細な操作手順・制限はREADME、実行した検査結果はRELEASE_VALIDATION.mdに記録します。


0.3.24では共通スクリーンショットボタンも追加しました。既存のゲーム画面撮影を直接呼ぶ操作で、スキンや表示文字は画像に含めません。表示・配置・サイズ・透明度は既存設定に統合し、取り込みスキンの画面やボタンの定義は変更しません。空き領域がない場合だけ撮影ボタン用の余白を確保し、元のスキン全体を同じ比率で収めます。長押し移動はゲーム別・向き別の撮影ボタンの座標だけを保存し、他の配置やゲームデータを置き換えません。設定名は「スクリーンショットボタン」に統一しました。新しいカメラの図形とWebコードは独自作成のAGPL-3.0-or-laterです。

保存履歴は件数に加えて合計サイズを制限し、大きな自動ステート5件の単一IndexedDB値がブラウザ上限を超える問題を修正。従来の形式を維持し、最新側の履歴を残します。手動ステートを自動削除せず、書込失敗時の全体取消と巨大checkpoint時のbattery保存を確認しました。


保存時のセーブ比較では、毎回のUint8Arrayコピーと要素ごとのコールバックを除き、元の可視バイト範囲を直接比較します。ハッシュの一致だけで省略せず、全バイトと長さを照合します。保存形式・DB版・保存間隔・履歴数・ROM引き継ぎの原本検査と原子的な取消を維持しています。描画側も合成画像で比較しましたが、テクスチャ更新方法の変更には全体の時間短縮がなかったため採用していません。


1 MiB以上の保存では、同じ端末内の専用Workerが既存の保存トランザクションを実行します。画面側はスナップショットを保持し、成功応答を受けるまで保存完了とは表示しません。初期化できない場合は従来の処理へ戻ります。送信後に応答が途絶えた場合は同じスナップショットを再送せず、旧セッションを無効にする書き込みが完了してから次の保存を受け付けます。DBの版、履歴の形式、2人分をまとめて保存するトランザクションとゲームの排他ロックは維持します。保存中・無効化処理中は更新による再読み込みを待機させます。Workerと保存世代の管理は独自作成のAGPL-3.0-or-laterコードで、新しい外部サービスやライブラリは使用しません。
