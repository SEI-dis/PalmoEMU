# 上流の更新検出

`Detect upstream updates` は毎日 06:17 JST 頃（GitHub の混雑時は遅延）と手動実行で、
採用コア・参考実装の固定コミットを各リポジトリのブランチ先頭と比較します。
結果は Actions の実行サマリーと `upstream-update-review` 成果物の JSON / Markdown に残ります。
エラーと「更新なし」は区別し、どれかを取得できなければ実行を失敗として表示します。

```sh
node web/scripts/upstream-watch.mjs
```

GitHub API の公開メタデータだけを読みます。候補のソース・リリース資産をダウンロード・
実行せず、採用版のファイル、ライセンス承認、容量上限、セーブ形式、公開版を変更しません。
スケジュールから既存のビルドワークフローを自動起動することもありません。
採用済みコミットは `SOURCES.json` を参照するので、更新検出用に二重管理しません。
枝が戻った場合や分岐した場合は、単純な更新と区別して要確認にします。

mGBA 候補は、ソース・ビルド手順の安全性を確認後に、レポートに記載されたコミットを
既存の `Check upstream core update` 手動ワークフローへ渡せます。候補ビルドが成功しても、
ライセンスと対応ソース、セーブ／ステート互換性、ブラウザ動作のレビューを経てから採用します。
別途取り込んだバックポートもあるため、コミットの不一致だけで未対応とは判断しません。

## セーブ変換ツール

現在は作者から直接提供されたパッケージを採用しており、確認済みの公開更新フィードはありません。
この状態をレポートにも「提供ファイルを手動確認」と明記します。新しい提供ファイルには
[`start-save-migrate/README.md`](start-save-migrate/README.md) の隔離検査を適用してください。

作者が公開 GitHub リリースの配布先を提示した場合は、出所と公開範囲を確認し、
`upstream-sources.json` の `converter.feed` を次の形式へ変更します。

```json
{
  "kind": "github-release",
  "repository": "https://github.com/AUTHOR/REPOSITORY",
  "adoptedTag": "v1.0.5"
}
```

これは形式例で、現在の作者の配布先ではありません。`adoptedTag` は実際に採用したタグへ合わせます。
自動取得するのは最新の安定版リリースのタグだけです。作者の HTML / JS / build.py や配布ファイルを
自動実行せず、候補のバージョン・変換先・許可・回帰検証を確認してから手動で差し替えます。
アプリ利用者の ROM・セーブ・診断データはこのワークフローへ送られません。
