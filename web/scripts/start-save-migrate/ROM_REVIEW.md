- 判定器とは別にThumb命令を確認。ファイル位置0x1097fb2の分岐から下限関数0x10e3a10と上限関数0x10e3a20への呼び出し・拒否分岐を確認し、定数0x2401との比較および0xc4 << 6で0.36.2〜0.49.0の範囲を検証した。保存版を書き込む関数0x10e3a2cの値も0.49.0と一致する。
- 新しいポケモン・技・道具のID上限、実ゲームでの保存/再読み込みは未確認。PKSの自動組み込みや生成済みROMの公開はしない。

### 対応判断

提供版1.0.8の定義（0.48.0まで）は変更しない。0.49.0という版番号だけを追加したり、ポケモン・技・道具のID上限を推測で広げたりしない。今回の実ROMは既存の判定器で認識できるため、対応表に未登録の更新先でも、互換な旧セーブを変更せず引き継ぐ既存経路を使える。古いセーブに変換が必要なら、更新先が受け付ける確認済みの中間出力（最大0.42.5）を使い、以降のゲーム内更新を残す。この版番号更新だけを理由とする新しい変換処理は追加しない。

合成0.49.0 ROMの互換性条件を使い、旧版からのコピー・変換、原本/バックアップ/両スロット/RTC保持、最低版引き上げ時の拒否、0.49.0セーブから0.48.0への逆戻り拒否を検査した。これは実ROMのゲームプレイ確認ではない。新しいIDを含む0.49.0セーブの検査・再変換への対応は、根拠を取得してから別途判断する。

### 更新情報の取得

同日のGitHub APIは匿名アクセス上限により403を返した。固定の公式README URLへのGETは200で0.49.0を確認できた。アプリにはAPIが403/429の場合だけ公式READMEへ切り替える経路を追加。見出しの版と配布ファイル名の一致を確認し、既知の版より古いREADMEでは確認成功としない。情報確認の成功はセーブ互換性を意味しない。

## 2026-10-16: 0.50.0 と L形式

- 配布元commit: [80cb08adf9fe2005f7618dbbdbffcab10b54e839](https://github.com/pm-start/PokemonStart/tree/80cb08adf9fe2005f7618dbbdbffcab10b54e839)。CHANGELOGは旧セーブとの非互換と「セーブデータ移行ツール.html」の使用を明記している。READMEの古い「保存構造の変更なし」だけで互換と判定しない。
- HTMLはPKSの中に同梱され、単独のリポジトリファイルではない。調査は無視対象の作業場所で静的抽出/復号した。HTML SHA-256は3a6c4378e32ff3d975d4d3ba15fbd88955baec20c08b9ce6c05f9846cbd35b88。元HTML・PKS・パッチを配布しない。
- 提供された64MiB ROM（SHA-256 8d26d304d128ca8c6b411da2ed4fcb696b4ed547e2d4306916b959e146b24c3e）を読取専用確認し、ハッシュ不変。保存版0.50.0、下限0.36.2に加えてL形式必須を検証した。下限関数0x10e4768、上限0x10e4778、旧形式メニュー拒否0x1098376→0x10da074、loader0x10da0d4のSHEL/SHL2判定と旧形式フラグを組み合わせる。版番号やファイル名だけでL対応としない。
- 公式forwardは58byteボックス個体を60byteへ配置し、拡張レベル情報を移す。丸めはreverse側のみでforwardに導入しない。全50×30枠を2スロットで独立検証する。
- 公式の更新ガードは0x31ffであり、ROMが保存する0x3200とは異なる。0x31ffを最低対応版と誤認せず、新形式を検証した場合だけ0.50用に変換済みと認識する。0x10e47e2の初回更新判定を残すため0x3200へ先取り変更しない。
- 0x130f240からのnative更新表は0.38.1で0x5140〜0x5146を初期化する。0x31ffへの変換でこの補正が飛ばないよう、0.38.1未満は既存の検証済み旧ツールの補正を先に適用する。個体/道具/技の上限を推測して広げる修正は加えない。
- 旧/L混在を旧版として検査・コピーする経路を拒否し、新しいLスロットを古いROMへ入れない。既存Lは同じ対応範囲ならバイトを変更せず、将来ROMはnative形式ゲートが一致しない限り自動で対応済みとしない。

合成入力で公式ツールとの一致・3000枠・既存歴史補正・RTC・原本/バックアップ・破損拒否を検査する。これは実セーブでの全ゲーム内容や実iPhoneの検証ではない。


## 2026-10-16: 0.50.1と拡張セーブ判定

公式配布commitは[62ebfdded673b10fa4450b94494166da8147d2bd](https://github.com/pm-start/PokemonStart/tree/62ebfdded673b10fa4450b94494166da8147d2bd)。変更履歴には、0.50.0変換直後のぼうけんのしょ2・拡張ボックス利用不可と、0.50.1ツールでの修正が記されている。今回のHTMLは利用者から別途提供されたものを静的復号した。PKSを解読・実行してHTMLとの同一性を確認したとの主張はしない。HTML/復号JavaScriptのハッシュはcomponent.jsonに記録する。

提供ROMのSHA-256は5f92a78d3c13d669c1ae78e06722f006a0289a89c0c58d66116df1411289b56d。既存の構造判定でversion 0.50.1 / minimumSaveVersion 0.36.2 / saveFormat Lを確認。別の拡張領域判定器も一致し、補正位置は0x10dee3a、必要flash容量は6MiBだった。出荷中WASMの容量はRTC込み6291472bytesで、loadCompatibleMGBAが起動前の一時コピーの該当1byteだけを変更することを全ROMハッシュ比較で確認した。原ROMの読込前後ハッシュは一致。ゲームのフレームは実行しておらず、実セーブの継続・実iPhoneを検証したものではない。

ツールのforward writerは、counter>0なら反対側のmain bankをcounter-1で書き、physical sector 16を本来のbox pageとして使わない場合だけpage zeroの控えを置く。判定対象のsector 0/16が空の拡張sector 32/752と同じ内容にならないようにする修正。全消去状態や新規ゲームはこの変換を通らないため、従来の構造/コア容量限定の一時ROM補正は残す。将来ROMで命令構造が変わった場合に版番号だけで補正を強制する変更はしない。

L形式の開始版0.50.0と更新ガード0x31ffは変更しない。0.50.1専用の変換許可や出力stampの先取りは加えていない。既存Lは提供ツールと同じくバイト同一のまま保持し、既存の0.50.0変換結果を書き直す追加処理も入れない。今回の実ROMでは従来の実行時補正でこの旧出力/空flashの誤判定を扱える。将来ROMの対応は版番号でなく実際のnative判定を確認する。

正常な合成両スロットで、counter 0/1/2/7/0xffffffff × sparse/denseの10条件が提供0.50.1ツールのforward出力と全bytes一致。個体3000枠、メタデータ、main bank世代、実box pageとしてのsector 16、原本・RTC・非配置領域を確認した。修正前の変換結果ではraw flashの4組の比較が失敗し、修正後に通ることを回帰検査で確認する。
