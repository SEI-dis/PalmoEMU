- [README](https://github.com/pm-start/PokemonStart/blob/2cf8e7e5dd3142834e894af0c2d76f0ba8f456d4/README.md)は、旧版の「つづきから」で最後に回復した場所から始まると説明している。所持数拡張で保存構造を変更していないとの記載もあるが、新しい版の保存仕様全体の証明とは扱わない。
- このコミットの公開ファイルはREADME、CHANGELOG、0.49.0のPKSのみ。ゲームソース、数値テーブル、セーブ互換性の最低版を確認できる資料は含まれない。
- ローカルに提供された64MiBの0.49.0 ROMを読み取り専用で確認。既存の判定器で最低対応版0.36.2、保存版0.49.0を認識した。入力ファイルの確認前後のハッシュは一致し、ROM・セーブを配布物やネット要求へ含めていない。
- 判定器とは別にThumb命令を確認。ファイル位置0x1097fb2の分岐から下限関数0x10e3a10と上限関数0x10e3a20への呼び出し・拒否分岐を確認し、定数0x2401との比較および0xc4 << 6で0.36.2〜0.49.0の範囲を検証した。保存版を書き込む関数0x10e3a2cの値も0.49.0と一致する。
- 新しいポケモン・技・道具のID上限、実ゲームでの保存/再読み込みは未確認。PKSの自動組み込みや生成済みROMの公開はしない。

### 対応判断

提供版1.0.8の定義（0.48.0まで）は変更しない。0.49.0という版番号だけを追加したり、ポケモン・技・道具のID上限を推測で広げたりしない。今回の実ROMは既存の判定器で認識できるため、対応表に未登録の更新先でも、互換な旧セーブを変更せず引き継ぐ既存経路を使える。古いセーブに変換が必要なら、更新先が受け付ける確認済みの中間出力（最大0.42.5）を使い、以降のゲーム内更新を残す。この版番号更新だけを理由とする新しい変換処理は追加しない。

合成0.49.0 ROMの互換性条件を使い、旧版からのコピー・変換、原本/バックアップ/両スロット/RTC保持、最低版引き上げ時の拒否、0.49.0セーブから0.48.0への逆戻り拒否を検査した。これは実ROMのゲームプレイ確認ではない。新しいIDを含む0.49.0セーブの検査・再変換への対応は、根拠を取得してから別途判断する。

### 更新情報の取得

同日のGitHub APIは匿名アクセス上限により403を返した。固定の公式README URLへのGETは200で0.49.0を確認できた。アプリにはAPIが403/429の場合だけ公式READMEへ切り替える経路を追加。見出しの版と配布ファイル名の一致を確認し、既知の版より古いREADMEでは確認成功としない。情報確認の成功はセーブ互換性を意味しない。


### 提供ツール1.0.9の追加確認

同日、利用者から0.49.0対応のHTMLが提供された。既存70版の定義と変換アルゴリズムは同一で、0.49.0の種族上限1506・技上限1006・道具上限869、保存版0x3100が追加されている。作者の実セーブ確認は作者提供の根拠として記録し、PalmoEMUでの実プレイ検証と区別する。従来の修正を保持したまま定義を取り込み、新しいIDを含むセーブの検査へ対応する。0.42.5中間出力・ROM側の最低対応版の確認・無変換コピー・逆戻り拒否は維持する。この追加では実0.49.0 ROMの確認は繰り返していない。
