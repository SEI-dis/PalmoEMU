# PalmoEMU — ManicEMUの非公式Web版

アプリ名と公開URLをPalmoEMUへ変更しました。同じブラウザの通常タブでは、従来と同じ端末内の保存領域を使用します。

ManicEMUの画面・メニュー・設定をWeb向けに移植し、公開ソースの構成に沿って再現したアプリです。
Web版のコードはAGPL-3.0-or-laterで公開しています。「標準」の画像とスキンは新規に作成しました。別の選択肢として、CC BY 4.0で公開されたManicEMU標準スキン7機種を同梱しています。[クレジット](licenses.html#skins)を参照してください。

最終更新：2026-10-12。アプリのバージョンは `0.3.13` です。設定の下部に、使用中のバージョンとビルド番号を表示します。
この文書は同梱するWeb版の動作を説明します。

## 起動・更新

Node.jsを用意し、`web` フォルダーで `node scripts/serve.cjs` を実行します。
リポジトリのルートからは `node web/scripts/serve.cjs` です。既定URLは `http://127.0.0.1:4173/`。
通常の起動に `npm install` やコアの再ビルドは不要です。
開発サーバーは `127.0.0.1` に限定して待ち受けます。iPhoneからこのPCのループバックURLには接続できません。
iPhoneで使う場合は、端末からアクセスできるHTTPSの配信先を用意してください。

初めて開く場合は、その時点の公開版を読み込むため、更新操作は不要です。
更新を準備できたら、すべてのタブがライブラリか設定の一覧に戻り、保存や取り込みが終わった後に自動で反映します。
プレイ中・通信中・設定の編集中・ファイル選択中には再読込しません。
旧版や応答のないタブなど、安全を確認できない画面が残っている場合は待機します。
すべてのタブを閉じた後の切り替えと、手動更新も引き続き利用できます。
自動切り替え中は画面中央に「更新中…」と回転アイコンを約1.2秒以上表示し、切り替え後に「更新しました」と通知します。動きを減らす設定ではアイコンを静止させます。
オフライン中は今の版を使います。接続が戻ったら更新を確認し、ダウンロードに失敗した場合は今の版を残して再試行します。
更新時はコアを含むアプリ用ファイル一式（約20MiB）を確認・保存してから切り替えるため、更新直後もオフラインで使えます。
すぐ反映したい場合は、ゲームを保存して終了し、「設定」→「アプリの更新」を開きます。
更新画面以外のアプリのタブを閉じて「更新」を押してください。ROM・セーブ・ステートは引き継がれます。
**サイトデータは削除しないでください。**

更新・プライバシー・ライセンスの各ページの「戻る」で設定画面へ戻れます。

## タッチ操作

0.3.13では、指を離した通知を取り逃がしても、全指の接触終了や次の最初のタッチで残った入力を解除します。標準・ManicEMU同梱・追加スキンで共通の処理を使います。長押し・同時押し・通信番号などの入力操作は維持します。

## 互換性補正

0.3.12から、PokemonStart v0.40.0の未使用セーブ領域を誤判定する処理を補正します。mGBA Celioで6MiBの保存領域を扱えることと、ROM全体のSHA-256が下記に一致することを起動時に確認し、実行用のコピーだけを変更します。

`74bfec1e57712f505a303fd1a0ad3e8977b05b86ff12c17952af16553249ce8a`

元のROMファイル・端末内に保存したROM・保存先の識別子は変えません。認識のためにセーブへ印を書き込む処理も追加していません。別の版や修正版には適用せず、ROM・セーブの送信や同梱も行いません。

更新後はゲームを一度終了し、ゲーム内セーブから起動し直してください。古いステートには補正前の判定結果が残る場合があります。既存のステートは削除しません。

検証用に作成したセーブでは、冒険の書1を残して2を作成・保存し、両方から再開できることを確認しました。利用者の既存セーブ、長期の進行、実機iPhoneは未検証です。[検証記録](RELEASE_VALIDATION.md)に範囲を記載しています。

## クラッシュ診断

「設定 → クラッシュ診断」から、エラー記録と現在の環境情報をJSONファイルに書き出せます。
記録は初期状態でオンで、直近5件を端末のlocalStorageに保存します。オフにする、記録だけ削除する、書き出す内容を事前に確認する操作もできます。
記録するのは日時、アプリの版、ブラウザ・OSの種類、使用コア、処理の状態、エラーの種類、アプリ内の発生箇所などです。ROM・セーブ・ゲーム名・生のエラーメッセージ・メモリの中身は含めず、自動送信もしません。保存できない場合は、そのタブ内だけで保持します。
ブラウザごと終了した瞬間の詳細や、OSが出力するメモリダンプは取得できません。前回のプレイが正常終了していなかった場合は、次回プレイ開始時にその事実を記録します。セーブの復旧は既存のバックアップ機能を使います。

## 対応機種

| 機種 | コア | インポートする拡張子 |
| --- | --- | --- |
| NDS（実験版） | DeSmuME 2015 / melonDS | `.nds` |
| GBA | mGBA celio edition / VBA-Next（32MiBまで） | `.gba` |
| GB・GBC | mGBA celio edition / jgenesis | `.gb` / `.gbc` |
| FC | FCEUmm / jgenesis | `.nes` |
| SFC | Mesen-S / jgenesis | `.sfc` / `.smc` |
| MD | ClownMDEmu / jgenesis | `.md` / `.gen` / `.smd` / `.bin` |

ROMの受付上限はNDSが512MiB、それ以外が64MiBです。上限内でもゲームごとの動作は保証しません。
mGBA Celioは6MiBまでの拡張セーブに対応します。通常のGBAゲームのセーブ容量を強制的に増やす設定ではありません。

ZIPは解凍してから追加します。3DSなど、表にない機種のコアは組み込まれていません。

各コアは固定バージョンのソースからWASMにビルドしています。ソースとビルド手順は `sources/` にあります。
ゲーム詳細の「コアを変更」で選択します。セーブ・ステート・復旧データはコアごとに保存し、元のコアへ戻すと以前のデータを使えます。64MiBのGBA ROMではVBA-Nextを選択できません。
jgenesisのセーブ出力はSRAMとRTCなどをまとめた `.jgsav` です。追加コアの制限とビルド手順は [こちら](sources/alternate-web/BUILD.md)、64MB対応コアの更新候補を検査する手順は [CORE_UPDATES.md](CORE_UPDATES.md) を参照してください。

旧版のSnes9x・Genesis Plus GX・EmulatorJSで保存したステートは読み込めません。
ゲーム内セーブは形式が合えば使用できます。旧セーブはライブラリの
「… → セーブデータをエクスポート」から取り出せます。形式が合わなくても、既存データは削除しません。

## NDS（iPhone向け実験版）

`.nds` をインポートすると、NDS専用のダークスキンで起動します。縦向きは同じ大きさの2画面を上下に並べ、
操作部を下にまとめます。横向きは左に大きいメイン画面、右上にサブ画面、右下にABXYなどを配置し、
十字キーとLはメイン画面に重ねます。2画面とも4:3を維持し、下画面に直接タッチできます。
「画面切り替え」で2画面の位置を入れ替えられます。A/B/X/Y、L/R、START/SELECTに対応します。
DeSmuMEの省電力モードは初期状態でオンです。ゲームの内部速度を保ちつつ描画を約30fpsに抑えます。
ゲームメニューでオフにすると通常の描画頻度になります。重い場合は映像フィルターをピクセルにしてください。

ゲーム内セーブの自動保存とインポート／エクスポート、最大5回分のバックアップ・自動ステート、
端末内の手動ステート保存・再開に対応します。ステート単体のインポート／エクスポートはありませんが、設定とセーブをまとめたバックアップには含まれます。
DeSmuMEはHLE、melonDSはBSDライセンスのFreeBIOSを使って直接起動します。市販機から抽出したBIOSは同梱しません。
ダークスキンの縁のアクセントは機種標準＋4色から選べます。外部NDSスキンにも対応しています。DSi、Wi-Fi通信、実マイク入力は未対応です。
ROMの受付上限は512MiBですが、大きいROMはiPhoneのメモリ上限で起動できない場合があります。
自作テストプログラムでWindowsのEdge / WebKitを検証済みです。市販ゲームの互換性、
iPhone実機の速度・発熱は未検証です。

## 基本操作

- 「インポート」から端末内のROMを追加します。通常のプレイでROMやセーブをサーバーへ送信しません。
- 追加が終わるまで、ファイル名・件数・読み込み済み容量と「読み込み／重複確認／保存」の段階を表示します。確認・保存中の残り時間は推測表示しません。大きなROMの読み込み・ハッシュ・保存は画面操作とは別のWorkerで処理します。
- 同じ画面でスキンの追加・変更や、ゲームを選んでセーブデータの読み込みもできます。
- タッチ、キーボード、標準的なゲームパッドで操作できます。
- 音量や速度は共通設定またはゲームごとの設定で変更できます。速度ボタンかTabキーで、1→2→3→4→5→1倍と切り替わります。ボタンには現在の倍率を表示します。
- 倍速中の音程維持は全対応コアで常時有効です。テンポはゲームの倍速に合わせたまま音の高さを保ちます。オン／オフの設定はなく、以前オフにした共通設定やゲーム別設定も適用しません。
- 音程維持は独自のWSOLA方式で処理し、1倍速では音声を加工しません。倍速時は短い音声バッファを使うため遅延が加わり、高倍率では音質の変化や処理負荷が増えます。音楽だけを等倍のテンポにする機能はありません。iPhone実機での音質・負荷は未検証です。
- 通常は約60fpsで動作します。速度は端末の性能によって変わります。
- 映像フィルターで見た目を調整できます。ゲーム内部の解像度を上げる機能ではありません。
- 「設定 → 映像とフレームレート」またはゲームメニューの「シェーダー」で「輪郭補正4倍（高品質）」を選べます。Scale4xで元の色を保ちながら輪郭を細かく補正します。負荷が増えるため、動作が重い場合は「輪郭補正2倍」や「ピクセル」に戻してください。
- 映像フィルターは「ピクセル」「なめらか」「スキャンライン」「輪郭補正2倍」「輪郭補正4倍（高品質）」です。ManicEMUの3DS用「高度シェーダー」と同じ機能ではありません。
- 動作の軽さを優先する場合は、映像を「ピクセル」、速度を「1倍」にしてください。
- チートに対応するコアでは、コードを入力して追加します。ゲームのバージョンに合うコードを使用してください。VBA-Next・melonDS・jgenesisのチートはこのWeb版では未対応です。
- 別のタブやアプリへ移ると一時停止します。戻ったら「タップして再開」を押してください。
- ゲーム画面全体（余白・保存状況・FPS表示を含む）で、長押し時のコピーメニュー・文字選択・画像ドラッグを抑止します。ゲームの長押し操作は使えます。部屋番号やチートなどの入力欄ではコピー／貼り付けを残しています。ダブルタップによる拡大も抑止し、通信パネルのスクロールは維持します。ゲーム画面外のズームは制限しません。iPhone実機のジェスチャーは未検証です。

## ライブラリの整理

機種・分類・お気に入り・ゲーム名の条件を組み合わせて絞り込めます。
分類は「未分類」「プレイ中」「クリア済み」「あとで遊ぶ」の4種類で、ゲーム詳細の「分類を変更」からも設定できます。
進行状況を手動で整理するための分類で、ゲームの起動やセーブ内容には影響しません。

「並べ替えと表示方法」では、名前順／名前の逆順／最近遊んだ順／追加が新しい順／プレイ時間が長い順を選べます。
表示は「機種ごと」「分類ごと」「まとめて表示」から選択し、並べ替えと表示方法をこのブラウザに保存します。

「選択」を押すとゲームの起動前メニューを開く代わりに複数のゲームを選べます。「すべて選択」は現在の絞り込み結果だけが対象です。
分類の変更、お気に入りへの追加／解除、削除をまとめて操作できます。絞り込み条件を変更すると選択を解除します。
削除前には対象名と件数を表示し、確認後にこのブラウザ内のROM・各コアのセーブ・ステート・保存履歴をまとめて削除します。端末上の元ファイルは残ります。
対象のどれかが別タブでプレイ中の場合は削除しません。保存処理が失敗した場合も一部だけ削除せず、選択を保って再操作できます。

選択モード・並べ替え・一括操作はManicEMUの固定版ソースを参考にしたWeb実装です。
この進行状況分類はPalmoEMUの追加機能で、ManicEMUの機種の派生カテゴリ変更とは異なります。
分類とお気に入りは端末内に保存し、一括バックアップにも含めます。外部へ送信しません。

## ゲーム詳細とメニュー

ライブラリのROM（カバー・名前）を選ぶと、ManicEMUのGameInfoView / GameInfoDetailViewに基づく
ゲーム詳細・設定を開きます。プレイ履歴・「…」・起動リンクも同じ詳細画面へ進みます。
選択だけではコアを起動せず、セーブやプレイ履歴も変更しません。「プレイ」を押すと起動します。
カバー、名前、プレイ履歴、赤いプレイボタンを上部に固定し、設定グループだけをスクロールします。
起動前のゲーム詳細から開いた子画面は、×／Esc／背景の操作で元のゲームメニューへ戻り、スクロール位置を保ちます。ゲーム詳細の×でライブラリへ戻ります。保存処理などで閉じられない間は、Esc／背景の操作も無効です。プレイ中は従来どおり子画面を閉じるとゲームへ戻ります。
セーブステートの一覧・再開、ゲーム内セーブのインポートとエクスポートは起動前にも使えます。
セーフモードはチートを無効にし、自動ステートを復旧せずゲーム内セーブから起動します。
機能順序設定とゲームショートカットはプレイ中のメニューにも反映されます。
起動リンクは、このブラウザにあるゲームの詳細を開きます。他の端末へROMを転送する機能ではありません。
ROMファイルの共有・書き出し機能はありません。セーブデータのインポート／エクスポートは利用できます。

ゲーム詳細やプレイ中に変えた速度・音量・ミュート・映像フィルター・画面スケーリング、
振動・デッドゾーン・コントロール表示・FPS表示・NDSの画面入れ替え／省電力・巻き戻し記録は、そのゲームの設定として保存します。
変更していない項目は「設定」画面の共通設定を使います。「共通設定を使用／このゲームの設定」で適用範囲を確認でき、
ゲームの個別設定をリセットすると共通設定へ戻ります。リセットでROM・セーブ・コア選択・チート・スキンは消しません。
外観・自動保存などは引き続き共通設定です。キー割り当てと連射設定は、後述の機種／入力機器単位で保存します。
3DS専用設定、AirPlay、TriggerProなど現在のコアやブラウザで使えない項目は表示しません。
参照元のSwift原本と対応表は sources/manicemu-ui/ にあります。

## カバー画像

ゲーム詳細の「カバー変更 → 画像を選ぶ」から、利用する権利のあるPNG・JPEG・WebPを選べます。
画像は端末内で縮小し、IndexedDBへ保存します。画像の検索や外部からの自動取得は行いません。
既に保存したカバーは維持し、再表示時に外部へ接続しません。

## 保存・復旧

ROM・セーブ・ステートの保存先は端末内のIndexedDBです。OPFSは使用していません。
共通設定と入力設定はlocalStorage、ゲーム別設定はIndexedDBのライブラリ情報、アプリ本体のオフライン保存はCache Storageを使います。
ゲームの処理は端末内で行い、ROMやセーブをアップロードするAPIはありません。
初回・未取得コア・オフライン保存・更新ではアプリのファイルを取得します。
通信プレイを開始した場合は、別途ゲームの通信データを相手と交換します。
確認した範囲と例外は `PRIVACY_AUDIT.md` に記録しています。

ゲーム内の「レポート」などは自分で行ってください。端末への自動保存はゲーム内のセーブ操作を代行しません。

| 保存の種類 | 動作・保持数 |
| --- | --- |
| ゲーム内セーブ | 自動保存が有効ならプレイ中に約10秒ごとに端末へ保存。内容が変わったときは変更前のデータを最大5回分保持 |
| 自動ステート | 自動ステート保存が有効なら約20秒ごとに保存。直近5回分を保持。復元前や終了時などにも保存 |
| 手動ステート | 毎回新しく追加。5個までの固定スロット制ではなく、端末の空き容量の範囲で保存 |

「設定 → 一般」の自動ステート保存と、「設定 → セーブと保存容量」のセーブ自動保存を切り替えられます。
自動ステート保存を有効にした場合はゲーム内セーブも一緒に保存します。

ステートは、プレイ中の状態を丸ごと保存したものです。復旧用の状態が残っている場合は、
異常終了後の起動時に再開する画面が表示されます。通信中はステートを保存しません。

画面の `save` とメニューの「セーブ」は確認後に新しい手動ステートを追加します。
`load` は最新の手動ステートを確認して読み込み、読み込み前の状態も復旧用に残します。
「セーブステートを確認」で「手動／自動」を
切り替え、画像と日時を見て「続ける」を押すと再開できます。手動のステートを削除する場合は
「編集」で選択し、「削除」を押して確認します。旧版の3スロットも引き継ぎます。
一覧の枠は保存件数で伸縮しません。手動／自動を切り替えてもボタンの位置を保ち、
件数が多い場合は一覧内をスクロールします。枠の高さは画面サイズに合わせます。

右上の「保存済み」は、端末への保存が完了した時刻です。保存中・保存失敗もここに表示します。
詳しい保存状況は「セーブステート → 自動 → 保存状況」で確認できます。
ゲーム内セーブの履歴は、プレイ中の「セーブデータ・バックアップ → バックアップ」から復元・書き出しできます。
ゲーム内セーブは単体ファイルとしてインポート／エクスポートできます。手動ステート・復旧用の履歴は、次の一括バックアップで持ち出せます。
容量不足で端末への保存に失敗しても、ファイルへの書き出しは可能です。
データの破損検査や、同じゲームを複数のタブで起動させない仕組みも備えています。

**大切なセーブはファイルにも書き出してください。** 端末の故障やサイトデータの削除には
端末内のバックアップだけでは備えられません。電源断の直前まで復旧できるとは限りません。

## コントローラー・連射・押しっぱなし

「設定 → コントローラー・キーボード」またはゲームメニューのコントローラー設定を開きます。
「ボタン割り当て」で機種と入力機器を選び、変更したい操作を押してから実際のキー・ゲームパッドのボタンや軸を入力します。
キーボード、ゲームパッド共通、ブラウザが識別する接続中のゲームパッド別に保存し、同じ機種のゲームで使用します。
同じ種類のゲームパッドをブラウザが同じIDで報告する場合は、同じ設定を使います。個別設定のないパッドは共通設定を使います。
割り当ての解除、入力待ちのキャンセル、選択した機種／入力機器の初期化ができます。

ゲームの各ボタンに加え、メニュー・ステート保存・クイックロード・速度切り替え・巻き戻しを割り当てられます。
標準キーは矢印、X/Z、Enter/Shift、対応機種ではA/S・W/Q等。特殊操作はEsc、F5、F8、Tab、Rです。
保存・ロードでは既存の確認画面を使い、巻き戻しは対応機種で記録がある場合だけ動きます。

「連射・押しっぱなし」では、各ボタンを通常／連射／押しっぱなし／両方から選びます。
連射周期は50〜1000ms（8段階、初期値100ms）。タッチ・キーボード・ゲームパッドに共通して適用します。
押しっぱなしは1回押して固定し、もう1回押すと解除します。一時停止、タブの非表示・フォーカス喪失、
入力機器の切断、ゲームの終了などでも解除します。通信中は操作補助とメニュー以外の特殊操作を停止します。
ManicEMUのTriggerProのマクロ編集・条件分岐・複数操作の自動実行を移植した機能ではありません。

## 巻き戻し

ゲーム詳細またはゲームメニューで「巻き戻しを記録」をオンにすると、プレイ中の状態をRAMに記録します。
初期状態はオフです。メニューの「最大3秒戻す」、割り当てた入力、対応スキンの巻き戻し操作で、残っている記録の範囲へ戻ります。
記録はゲーム内時間の約0.5秒ごと、最大10秒・21件です。メモリ上限に達したら古い記録を捨てるため、戻せる時間は短くなる場合があります。

対象はGB/GBCのmGBA・jgenesisと、GBAのmGBA・VBA-Nextです。NDS・FC・SFC・MD・3DSは対象外です。
保持する履歴と失敗時の復元用コピーは合計8MiBまでで、1状態が4MiBを超える場合は安全に復元できないため記録を停止します。
コアが状態を書き出す際の一時メモリはこの保持上限とは別です。大きな拡張RAM／拡張セーブを使うROMでは利用できない場合があります。

CPU等の状態と、その時点のゲーム内セーブRAMを一緒に戻します。巻き戻しの操作自体では、端末の永続セーブを書き換えません。
復元中は入力・保存処理を止めます。再開後は通常の自動保存・終了時保存が行われるので、以前の進行も残したい場合は先に書き出してください。
ゲーム・コアの変更、ステートの読み込み、リセット、セーブのインポート、チート変更、コアエラー、通信開始で記録を消します。
記録は一時メモリだけで、終了・再読込・バックアップの対象には残りません。通信中は利用できません。

## 設定と全セーブをまとめてバックアップ

「設定 → セーブと保存容量 → まとめてバックアップ」で、端末内の設定・全ゲームの保存データを1つのJSONへ書き出します。
最新のゲーム内セーブを含めるには、先にプレイ中のゲームを終了してください。クラウド保存や自動アップロードはありません。

| 含むもの | 含まないもの |
| --- | --- |
| 全コア・GBA通信2Pを含むゲーム内セーブ、全手動ステート、各最大5回分のセーブ履歴・自動ステート | ROM・実機BIOS、ステートのスクリーンショット |
| 共通／ゲーム別の対応設定、コア選択、キー割り当て、連射・押しっぱなし設定、チート、編集した操作配置、分類・お気に入り | カバー画像、スキン画像・ファイル・選択状態、ゲーム名・ROMファイル名 |
| ROM照合用SHA-256・機種・容量、コア識別情報 | セッション、クラッシュ診断、オフラインキャッシュ、RAM内の巻き戻し記録 |

形式は `PalmoEMU-save-backup` バージョン1です。最大1000ゲーム・10000保存項目、保存データ合計128MiB、ファイル192MiBまでです。
上限を超えた場合は一部だけを書き出さず、エラーを表示します。ファイルは暗号化していません。セーブにはプレイヤー名などが含まれる場合があるため、個人用として保管してください。

復元先には利用する権利のある同じROMを先に追加します。ファイル選択後に内容・ハッシュ・対応コアを検査し、
一致するゲームとROM未追加の件数を表示します。選択しただけでは変更しません。確認すると、一致したゲームの保存データ・個別設定と共通設定を置き換えます。
ROM未追加のゲームは復元せず、既存のROM・カバー・ゲーム名を維持します。スキンは別途追加・選択してください。
分類・お気に入りを含むバックアップではその状態も復元します。これらの項目がない旧バックアップを読み込んだ場合は、現在の分類・お気に入りを保ちます。

すべてのタブでゲームを終了してから復元します。プレイ中のロック、破損・未対応項目、保存容量不足があれば復元を拒否します。
セーブ類は1回のIndexedDBトランザクションで置き換え、復元前のデータ・設定を端末内に1世代残します。
「復元前のバックアップを書き出す」から取り出せます。次の復元時に置き換わり、サイトデータを消すと失われます。
設定保存の途中で処理が止まった場合は、次回起動時に保留された設定を反映してから利用を開始します。
復元前バックアップにも同じ128MiB上限があります。上限内でもiPhone実機での最大容量の処理は未検証です。

## オフライン

「設定」→「オフラインで使う」→「ダウンロード」で必要なファイルを保存できます。
完了後はネットに接続せず遊べます。ROMはあらかじめライブラリに追加してください。
GBA通信にはネット接続が必要です。

## スキンとレイアウト編集

「設定 → スキン」で機種共通のスキンを選べます。
GB・GBC・GBA・FC・SFC・MD・NDSでは、従来の「標準」に加えて「ManicEMU」も選べます。既存の選択は変更しません。同梱版はオフライン保存の対象です。
ゲームごとの指定は、ライブラリの「… → スキン設定」またはプレイ中のメニューから変更できます。
「機種の設定を使う」を選ぶと共通設定に戻ります。ゲーム別の指定は再起動後も保持されます。
追加したスキンはプレビュー付きの一覧に残り、標準色に変えた後も選び直せます。
上部の「縦画面」「横画面」を切り替えて、それぞれ別のスキンを選べます。標準の色も向き別に保存します。
ゲーム別の「機種の設定を使う」も向き別です。端末を回転すると対応するスキンへ切り替わります。
以前の共通設定は両方の向きに引き継ぎ、片方を変更してももう片方は保持します。
最後に見ていた機種も保持します。削除は「編集」から選び、確認後に行います。

対応する全機種に専用スキンがあります。「機種標準」の配色に加え、パープル・グラファイト・
ミント・サンセットの4色を選べます。既存の色指定・配置設定は引き継ぎ、未指定時は機種標準になります。

| 機種 | 標準デザインとボタン構成 |
| --- | --- |
| GB | グレーと深い赤、斜めのA/B、十字キー、SELECT/START |
| GBC | クリアケース風、斜めのA/B、十字キー、SELECT/START |
| GBA | 丸みのあるワイド携帯機風、斜めのA/B、独立したL/R |
| FC | クリーム色と赤、横並びのB/A、SELECT/START |
| SFC | グレーの本体、青X・緑Y・赤A・黄Bのひし形配置、L/R |
| MD | ダーク本体、上段の小さいX/Y/Zと下段の大きいA/B/C、MODE/START |
| NDS | ダーク本体、上下／大小の2画面、ABXYとL/R |

「標準」スキンの画像はオリジナルのSVGです。画面の広さとノッチなどの余白に合わせ、
ボタンを下または左右に配置します。ゲーム画面の比率は保ち、回転やウィンドウのサイズ変更にも追従します。
プレビューも使用中の画面比率に合わせます。メニューやライブラリは表示幅に応じて折り返します。
「画面・ボタンのレイアウト」はManicEMUの「画面／ボタン」切替と移動・拡縮操作を参考にしています。
画面と各ボタンをドラッグして移動し、サイズスライダー・丸いハンドル・2本指のピンチで大きさを変更できます。
縦横比を維持し、画面外へはみ出さない範囲で調整します。ボタンは個別／まとめてサイズ・透明度を変更できます。
画面はボタンの背面に描画します。ボタンを画面に重ねても操作でき、透明度（0〜80%）は編集・プレビュー・プレイで共通です。
配置編集にはグリッドと吸着を用意しています。間隔は3段階で、中央線・端・ほかの対象の端や中心・左右対称の位置へ
近づけるとガイドを表示して吸着します。「横中央」「縦中央」、基準を選ぶ「高さをそろえる」「左右対称にする」でも整えられます。
左右対称は基準と同じ高さで中央線の反対側へ移動します。サイズは変えず、画面内に収まる範囲で位置を合わせます。
吸着をオフにすると自由に配置できます。キーボードの矢印キーやAltを押しながらのドラッグも吸着せず微調整できます。
グリッドとガイドは編集画面だけに表示され、プレイ画面には出ません。
「初期配置に戻す」は編集中の向きの画面とボタンを戻します。保存前ならキャンセルで変更を破棄できます。
NDSは「画面」の選択欄でメイン画面／サブ画面を個別に調整できます。画面切り替え時は表示内容と
タッチ入力が一緒に移動します。従来の2画面まとめての配置設定も保持します。画面だけの配置指定は
コントロール非表示時にも適用され、未指定時は2画面の表示領域を広げます。
縦・横の配置は別々に保存します。ゲーム別・機種共通の設定に対応し、標準スキンの全配色で共有します。
「保存」で確定します。保存したボタン位置は自動配置より優先します。
同梱ManicEMUスキンと外部スキンは作者の配置を保ったまま画面に収めます。配置編集は「標準」スキンで利用できます。
サイズは標準配置を100%とし、ボタンは50〜200%、画面は25〜200%の範囲で変更できます。
画面内に収まる大きさが上限なので、端末や対象によっては200%まで拡大できません。
キーボードでは選択対象を矢印キーで移動でき、サイズ変更ハンドルにフォーカスすると矢印キーで拡縮できます。
メニューの「コントロール非表示」をオンにするとボタンを隠せます。画面の配置を指定していない場合は、表示領域を広げます。
端末内の `.deltaskin` / `.manicskin` も追加できます。
PNG・JPEG・WebP・PDF、機種別・端末別の配置、複数画面と切り抜き、NDSのタッチ入力、
クイック保存・読込・早送り、可動スティック、Manicのボタン画像・押下アニメーションに対応しています。
色補正・ぼかし・発光・回転などはブラウザで再現します。Core Imageと完全に同じ描画ではありません。
未対応の効果・操作とCAF効果音は、取り込み後に注意点を表示します。
ファイルは40MiB以下、展開後100MiB以下です。対応範囲と検証内容は [SKIN_COMPATIBILITY.md](SKIN_COMPATIBILITY.md) を参照してください。
追加したスキンはサーバーへ送信しません。作者の利用条件に従って使用してください。

## GBA通信（Beta）

Celio方式に対応するGBAゲーム用です。すべてのGBAゲームに対応する機能ではありません。
通信パネルで次の3方式を選べます。

- オンライン：部屋番号で相手と接続。
- この端末で2台：同じROMをもう1台起動し、1P／2Pを切り替え。2Pは専用の保存領域を使い、前回のセーブ・ファイル・最初からを選べます。
- USB実機：PCのChrome / EdgeでWeb Serial対応のCelio変換器を選択。対応する実機通信ケーブルも必要です。iPhoneのSafariはUSB接続に非対応です。USB切断・中止で戻せるのはブラウザ側だけで、実機のセーブは復元できません。

端末内・USB通信では中継サーバーへ接続しません。端末内通信のセーブは正常終了時に2人分を1つのトランザクションで保存します。
中止時は1Pを通信前に戻し、保存済みの2Pデータは置き換えません。2Pセーブは通信パネルからファイルに書き出せます。
2台分のCPUとメモリを使うため、iPhone実機の速度やメモリ使用量は別途確認が必要です。USB実機との交換・対戦も未検証です。

ゲーム画面の上中央のWi-Fiボタン、またはゲームメニューの「通信」から開きます。
通信パネルを開いたままゲームを操作できます。パネル上部をドラッグして移動でき、
閉じても通信は続きます。部屋番号は欄内のコピーボタンでコピーできます。
パネル上部はWi-Fiマークと薄い「Beta」表記です。
Wi-Fiマークは待機中が黄色、接続中が緑です。パネルの「×」は非表示、「通信を中止」は接続終了です。

1. 一方が「部屋を作る」を押し、4桁の番号を相手に伝えます。
2. 相手が番号を入力して「参加」を押します。
3. 両方のゲームでケーブル通信の受付へ進みます。

liru55 / mgba-celio-webも同じCelioサーバーを選ぶと接続できます。
公開版のWASM・通信コードと、テスト用GBAプログラムで相互接続を確認しています。
対象バージョンと検査条件は LINK_COMPATIBILITY.md を参照してください。
実際のゲームで交換・対戦が完了することは未検証です。

オンライン通信を明示的に始めた場合だけ celio-server.up.railway.app へ接続します。
ROM・セーブファイルは送りませんが、ゲームの通信データはサーバー経由で相手に届きます。
サーバー側にはIPアドレスも伝わります。部屋番号にパスワード認証はありません。

通信前の状態を端末内へ保存します。通信中は1倍速に固定し、チート・セーブの自動保存・
ステート操作を止めます。ゲーム内で通信が正常終了すると結果を保存し、中止・切断時は
通信前へ戻します。接続後に別のタブやアプリへ移ると切断します。

## 変更後の生成ファイル

以下は `web` フォルダーで実行します。Node.jsとPython 3が必要です。
macOS / Linuxでは、例の `python` を `python3` に読み替えてください。

```sh
node scripts/build-offline.cjs
python -B -X utf8 scripts/package_source.py
```

`offline-manifest.js` はオフライン対象と更新識別用のハッシュ、
`sources/web-ui-source.zip` は配布するWeb実装のソースです。生成したZIPもGitへ含め、クリーンな取得直後から対応ソースを提供します。
UIやREADMEを変更した後も再生成してください。各コマンドの末尾に `--check` を付けると、
書き換えずに生成物と現在のファイルが一致するか検査できます。

配布内容の記録は確認後に更新します。次はリポジトリのルートから実行します。
`prepare-release.py` は `work/release` の専用コピーだけを作り直し、個人データや他の `work` の内容には触れません。

```sh
python -B -X utf8 web/scripts/audit-git.py
node web/scripts/build-offline.cjs
python -B -X utf8 web/scripts/prepare-release.py
python -B -X utf8 work/release/web/scripts/audit-content.py --record
```

生成された `work/release/web/RELEASE_CONTENT.json` を `web/RELEASE_CONTENT.json` へコピーします。
変更した依存物・素材・通信・テスト結果をレビューし、`RELEASE_REVIEW.json` の対象ハッシュと根拠を更新します。
`--record` はファイル一覧とハッシュの記録だけで、権利や公開可否を認定しません。続いて：

```sh
python -B -X utf8 web/scripts/package_source.py
python -B -X utf8 web/scripts/prepare-release.py
node work/release/web/scripts/check-release.cjs
```

この検査は開発出力、未登録ファイル、古い対応ソース・オフラインマニフェスト・確認記録を拒否します。
ソースZIPには固定時刻とファイル順を使い、同じソースなら同じ内容になります。
GitHub CIはこの検査とテストを行います。Pages公開ワークフローも既存の確認記録を検査し、自動で承認・再生成しません。

## GitHub Pagesで公開する

1. GitHub Pagesで利用できるリポジトリを用意します。GitHub Freeでは公開リポジトリが必要です。
2. この `web` フォルダーと `.github/workflows/ci.yml`、`.github/workflows/web-pages.yml` を配置します。
   元のiOSリポジトリの履歴や素材、`work` フォルダー、個人のROM・セーブは含めないでください。
3. 上記の手順で生成ファイルと配布内容の記録を更新します。現在の内容に対する確認を行い、
   `RELEASE_REVIEW.json` の対象ハッシュ・根拠を更新してから、`node scripts/check-release.cjs` の成功を確認します。
   確認記録を変更した場合もソースZIPを再生成します。
4. GitHub PagesのSourceをGitHub Actionsに設定します。`main`へpush後、同じコミットの
   「Validate Web release」が成功したら「Publish PalmoEMU」を`main`で手動実行します。
   公開ワークフローは同じコミットのCI成功を確認し、未確認・失敗の場合は停止します。
5. 公開後も `licenses.html`、`sources/`、`licenses/` を残します。
   改変した場合はソースZIP・ハッシュ・確認記録も更新してください。

このリポジトリの公開・更新・停止の詳細はリポジトリ内の `deployment/README.md` にまとめています。
ローカル開発URLと公開URLは保存領域が別です。移行時はセーブまたは一括バックアップを書き出し、公開版で手元の同じROMを追加して取り込んでください。

クレジット表記だけではライセンス条件を満たしません。著作権表示、ライセンス本文、変更通知、
対応するソースの提供を維持してください。確認記録は `LICENSE_AUDIT.md` と `RELEASE_REVIEW.json` にあります。
2026-10-10の検査対象と結果は RELEASE_VALIDATION.md に記録しています。以後の変更は再確認が必要です。

## 開発用のテスト

以下は `web` フォルダーで実行します。コア単体のテストはNodeのみで実行できます。

```sh
npm test
npm run test:cores
npm run test:nds
```

ブラウザテストにはPlaywrightと対応ブラウザを別途用意します。
多くのテストは起動済みの `http://127.0.0.1:4173/` を使います。
カバーのテストは自作PNGで端末内の保存・復元を検査し、旧設定があっても外部通信しないことを確認します。
テスト専用の自作カートリッジと独立したブラウザ環境を使い、利用者のROM・セーブや開いているタブには触れません。

- `PLAYWRIGHT_MODULE`: 既存のPlaywrightを使う場合のモジュールパス。省略時は `playwright` を読み込みます。
- `BROWSER_CHANNEL`: Chromium系のブラウザ。WindowsでEdgeを使う場合は `msedge`。一部のテストはこれが既定値です。
- `BROWSER_ENGINE`: 対応テストで `webkit` を指定するとPC版WebKitを使用します。既定は `chromium` です。
- `PYTHON`: Python実行ファイルのパス。PythonがPATHにない環境で使います。
- `NPM_CLI`: npmがPATHにない場合の `npm-cli.js` のパス。通信テスト準備で使います。
- `TEST_URL`: 対応テストのアクセス先。固定の4173番ポートを使うテストもあるため、通常は既定URLで起動してください。

WebKit対応は browser / visibility / state-ui / responsive-skins / layout-sizing / layout-alignment / runtime-performance /
speed-control / pitch-audio / privacy / native-menu / game-navigation / library / library-bulk / nds-browser / nds-skin / system-skins / link-panel / direct-link / haptics / room-link / covers / multicore / skin-compatibility / skins / bundled-skins / skin-orientation / update / extended-save / rom-import / diagnostics / game-preferences / input-controls / backup / rewind の各 `.cjs` です。
音声APIのないWebKitビルドでは、音声検査をスキップしたことを表示します。
PC版WebKitの検査は、iPhone実機の速度・発熱・消費電力やOS標準メニューの検証を代替しません。

Celio公開実装との相互接続は `node tests/room-link.cjs` で検査します。
`CELIO_SERVER_ROOT` と `CELIO_REFERENCE_ROOT` に固定版サーバーと参照実装を指定する必要があります。
検証した版と条件は [LINK_COMPATIBILITY.md](LINK_COMPATIBILITY.md) を参照してください。

### 全件実行

Node.js 24、Python 3.12以上、Playwright 1.62.1と対象ブラウザを使用しています。
Playwrightは開発用の依存物で、アプリの配布物へ含めません。Windows CIはEdgeとPC版WebKitを使用します。
リポジトリのルートから通信の固定テスト依存物を用意してから実行します。

```sh
python -B -X utf8 web/scripts/prepare-link-tests.py
```

表示された `CELIO_SERVER_ROOT` と `CELIO_REFERENCE_ROOT` を環境変数に設定してください。
準備スクリプトは公開コードとnpm依存物を取得します。ROM・ゲーム画像は取得しません。
実際のテストはローカル中継だけを使い、公開Celioサーバーへ接続しません。
開発サーバー起動後に次を実行します。

```sh
node web/scripts/test-all.cjs
node web/scripts/test-all.cjs --webkit
```

結果は無視対象の `web/test-results/suite-*` に保存します。一件でも失敗すると非ゼロ終了します。
CIはEdge・WebKitを各3組、計6ジョブに分けて並列実行し、実行中のログを逐次表示します。
`--shard=1/3` で1組だけ実行でき、`--list` で対象一覧を確認できます。全組の成功が公開条件です。
個別の失敗を修正した後は、該当テストと関連テストを再実行してください。

CIや起動済みサーバーのない環境では `--serve` を付けます。テスト側でループバックサーバーを起動し、
準備完了後に検査を開始して、成功・失敗にかかわらず終了時に自分のサーバーだけを停止します。
`--serve` は空いているポートを自動で割り当てるため、開発サーバーと併用できます。

```sh
node web/scripts/test-all.cjs --serve
node web/scripts/test-all.cjs --serve --webkit
```

## タッチの振動

Vibration APIがあるブラウザで、画面ボタンを押すと8ms／20msの振動を要求します。
非対応ブラウザでは設定を無効にし、非対応と表示します。iPhone Safariは非対応です。
Android Chrome系でも、振動モーターやOS設定に左右されます。ブラウザAPIの呼び出し成功は実際の振動を保証しません。
