## 対応機種

| 機種 | コア | インポートする拡張子 |
| --- | --- | --- |
| NDS（実験版） | DeSmuME 2015 / melonDS | `.nds` |
| GBA | mGBA celio edition / VBA-Next（32MiBまで） | `.gba` |
| GB・GBC | mGBA celio edition / jgenesis | `.gb` / `.gbc` |
| FC | FCEUmm / jgenesis | `.nes` |
| SFC | Mesen-S / jgenesis | `.sfc` / `.smc` |
| MD | ClownMDEmu / jgenesis | `.md` / `.gen` / `.smd` / `.bin` |

ROMの受付上限はNDSが512MiB、GBA（mGBA）が128MiB、それ以外が64MiBです。上限内でもゲームごとの動作は保証しません。
mGBA Celioは16MiBまでの拡張セーブに対応します。通常のGBAゲームのセーブ容量を強制的に増やす設定ではありません。
大きなROMの起動時は、mGBA内の二重コピーを避け、終了時にコアのメモリへの参照を解放します。端末全体の空きメモリとは別にブラウザ側の上限もあるため、メモリ不足が必ず解消するものではありません。

ZIPからも追加できます（[対応範囲と上限](#zipからのゲーム追加)）。表にない機種は通常のゲーム追加に対応していません。

各コアは固定バージョンのソースからWASMにビルドしています。ソースとビルド手順は `sources/` にあります。
ゲーム詳細の「コアを変更」で選択します。セーブ・ステート・復旧データはコアごとに保存し、元のコアへ戻すと以前のデータを使えます。64MiBのGBA ROMではVBA-Nextを選択できません。
jgenesisのセーブ出力はSRAMとRTCなどをまとめた `.jgsav` です。追加コアの制限とビルド手順は [こちら](sources/alternate-web/BUILD.md)、mGBAコアの更新候補を検査する手順は [CORE_UPDATES.md](CORE_UPDATES.md) を参照してください。

旧版のSnes9x・Genesis Plus GX・EmulatorJSで保存したステートは読み込めません。
ゲーム内セーブは形式が合えば使用できます。旧セーブはライブラリの
ゲーム詳細またはゲームメニューの「ゲーム内セーブ・保存履歴」から読み込み・書き出しできます。形式が合わなくても、既存データは削除しません。

## 基本操作

- 「インポート」から端末内のROMを追加します。通常のプレイでROMやセーブをサーバーへ送信しません。
- 追加が終わるまで、ファイル名・件数・読み込み済み容量と「読み込み／重複確認／保存」の段階を表示します。確認・保存中の残り時間は推測表示しません。大きなROMの読み込み・ハッシュ・保存は画面操作とは別のWorkerで処理します。
- 同じ画面でスキンの追加・変更や、ゲームを選んでセーブデータの読み込みもできます。
- タッチ、キーボード、標準的なゲームパッドで操作できます。
- 音量や速度は共通設定またはゲームごとの設定で変更できます。速度ボタンかTabキーで、1→2→3→4→5→1倍と切り替わります。ボタンには現在の倍率を表示します。
- 倍速中の音程維持は全対応コアで常時有効です。テンポはゲームの倍速に合わせたまま音の高さを保ちます。オン／オフの設定はなく、以前オフにした共通設定やゲーム別設定も適用しません。
- 音程維持は独自のWSOLA方式で処理し、1倍速では音声を加工しません。倍速時は短い音声バッファを使うため遅延が加わり、高倍率では音質の変化や処理負荷が増えます。音楽だけを等倍のテンポにする機能はありません。iPhone実機での音質・負荷は未検証です。
- 通常は約60fpsで動作します。速度は端末の性能によって変わります。
- 映像フィルターで見た目を調整できます。ゲーム内部の解像度を上げる機能ではありません。
- 「設定 → 映像とフレームレート」またはゲームメニューの「映像フィルター」で「輪郭補正4倍（高品質）」を選べます。Scale4xで元の色を保ちながら輪郭を細かく補正します。負荷が増えるため、動作が重い場合は「輪郭補正2倍」や「ピクセル」に戻してください。
- 映像フィルターは「ピクセル」「なめらか」「スキャンライン」「輪郭補正2倍」「輪郭補正4倍（高品質）」「LCD」「CRT」「xBRZ」です。対応機能と負荷は[フィルターとコア最適化](#フィルターとコア最適化)を参照してください。
- 動作の軽さを優先する場合は、映像を「ピクセル」、速度を「1倍」にしてください。
- チートに対応するコアでは、コードを入力して追加します。ゲームのバージョンに合うコードを使用してください。VBA-Next・melonDS・jgenesisのチートはこのWeb版では未対応です。
- 別のタブやアプリへ移ると一時停止します。戻ったら「タップして再開」を押してください。
- ゲーム画面全体（余白・保存状況・FPS表示を含む）で、長押し時のコピーメニュー・文字選択・画像ドラッグを抑止します。ゲームの長押し操作は使えます。部屋番号やチートなどの入力欄ではコピー／貼り付けを残しています。連打・2本指操作によるページ拡大も抑止し、通信パネルのスクロールとスキンの操作は維持します。ホーム・インポート・設定ではダブルタップ拡大を抑え、ピンチ拡大と通常のスクロール・文字編集は維持します。iPhone実機のジェスチャーは未検証です。

- メニューは矢印キーやゲームパッドの方向入力で移動、Aで決定、B／STARTで戻れます。文字入力欄では通常の編集を優先します。

## ZIPからのゲーム追加

端末内で順番に解凍し、対応ROMだけを取り込みます。ZIPは576 MiB、展開するROMの合計は512 MiB、書庫全体は256項目まで。ROM単体はNDS 512 MiB、その他64 MiBまでです。暗号化・分割・ZIP64・ネストした書庫は対象外。途中で失敗した場合も、それまでに追加したゲームは残り、件数を表示します。同じROMの再追加では既存データを上書きしません。`.pks`は扱いません。

複数ファイルの追加では、読み込めないファイルを結果に残して次のファイルを試します。容量不足など保存機能全体の失敗ではそこで止め、未処理の件数を案内します。すでに追加したゲームは残ります。

## ROMパッチ

インポートの「ROMパッチ」はIPS・BPS・UPSに対応。ROM・パッチは各64 MiBまで、結果を新しいファイルとして保存します。既存ゲームやセーブを置き換えません。BPS／UPSはCRCを検証し、IPSは作者の指定ROMを利用者が確認します。

セーブ・ステート・バックアップ・診断・パッチ結果の書き出しは、用意したファイルを確認して「保存」します。対応環境では保存先選択や共有画面を開きます。通常のダウンロードでは「ダウンロードを開始しました」と表示し、保存完了とは区別します。

## ライブラリの整理

機種・分類・お気に入り・ゲーム名の条件を組み合わせて絞り込めます。
分類は「未分類」「プレイ中」「クリア済み」「あとで遊ぶ」の4種類で、ゲーム詳細の「分類を変更」からも設定できます。
進行状況を手動で整理するための分類で、ゲームの起動やセーブ内容には影響しません。

「並べ替えと表示方法」では、名前順／名前の逆順／最近遊んだ順／追加が新しい順／プレイ時間が長い順を選べます。
表示は「機種ごと」「分類ごと」「まとめて表示」から選択し、並べ替えと表示方法をこのブラウザに保存します。

「選択」を押すとゲームの起動前メニューを開く代わりに複数のゲームを選べます。「すべて選択」は現在の絞り込み結果だけが対象です。
分類の変更、お気に入りへの追加／解除、削除をまとめて操作できます。絞り込み条件を変更すると選択を解除します。
削除前には対象名と件数を表示し、確認後にこのブラウザ内のROM・各コアのセーブ・ステート・保存履歴をまとめて削除します。端末上の元ファイルは残ります。
対象のどれかが別タブでプレイ中の場合は削除しません。保存処理が失敗した場合も一部だけ削除せず、選択を保って再操作できます。

選択モード・並べ替え・一括操作はManicEMUの固定版ソースを参考にしたWeb実装です。
この進行状況分類はPalmoEMUの追加機能で、ManicEMUの機種の派生カテゴリ変更とは異なります。
分類とお気に入りは端末内に保存し、一括バックアップにも含めます。外部へ送信しません。

## ゲーム詳細とメニュー

クイックスタートがオフの場合、ライブラリのROM（カバー・名前）を選ぶと、ManicEMUのGameInfoView / GameInfoDetailViewに基づく
ゲーム詳細・設定を開きます。「プレイ」を押すと起動します。クイックスタートをオンにすると、ゲームの選択で直接起動します。
「…」や起動リンクからは詳細画面を開きます。詳細を開くだけではコアを起動せず、セーブやプレイ履歴も変更しません。
カバー、名前、プレイ履歴、赤いプレイボタンを上部に固定し、設定グループだけをスクロールします。
起動前のゲーム詳細から開いた子画面は、ヘッダーの「戻る」／Esc／背景の操作で元のゲーム詳細へ戻り、スクロール位置を保ちます。二択の確認画面は×とキャンセルで取り消せます。ゲーム詳細の×でライブラリへ戻ります。保存処理などで閉じられない間は、Esc／背景の操作も無効です。プレイ中は従来どおり子画面を閉じるとゲームへ戻ります。
セーブステートの一覧・再開、ゲーム内セーブのインポートとエクスポートは起動前にも使えます。
セーフモードはチートを無効にし、自動ステートを復旧せずゲーム内セーブから起動します。
機能順序設定とゲームショートカットはプレイ中のメニューにも反映されます。上部に表示するショートカットは一覧で重複表示せず、非表示にした操作は一覧に残します。
起動リンクは、このブラウザにあるゲームの詳細を開きます。他の端末へROMを転送する機能ではありません。
ROMファイルの共有・書き出し機能はありません。セーブデータのインポート／エクスポートは利用できます。

ゲーム詳細やプレイ中に変えた速度・音量・ミュート・映像フィルター・画面スケーリング、
振動・デッドゾーン・コントロール表示・FPS表示・NDSの画面入れ替え／省電力・巻き戻し記録は、そのゲームの設定として保存します。
変更していない項目は「設定」画面の共通設定を使います。「共通設定を使用／このゲームの設定」で適用範囲を確認でき、
ゲームの個別設定をリセットすると共通設定へ戻ります。リセットでROM・セーブ・コア選択・チート・スキンは消しません。
外観・自動保存などは引き続き共通設定です。キー割り当てと連射設定は、後述の機種／入力機器単位で保存します。
3DS専用設定、AirPlay、TriggerProなど現在のコアやブラウザで使えない項目は表示しません。
参照元のSwift原本と対応表は sources/manicemu-ui/ にあります。

## カバー画像

ゲーム詳細の「カバー変更 → 画像を選ぶ」から、利用する権利のあるPNG・JPEG・WebPを選べます。
画像は端末内で縮小し、IndexedDBへ保存します。画像の検索や外部からの自動取得は行いません。
既に保存したカバーは維持し、再表示時に外部へ接続しません。

## 言語

「設定 → 言語」で日本語・英語・中国語（簡体字／繁体字）・韓国語・スペイン語・フランス語・ドイツ語・ポルトガル語を選べます。初期設定の「自動」は、ブラウザの優先言語から最初に対応するものを選び、対応言語がなければ英語にします。中国語はスクリプト指定を優先し、台湾・香港・マカオは繁体字、それ以外は簡体字です。手動の選択はこのブラウザに保存し、次回も使用します。設定一覧で変更するとページを再読み込みします。ROM・セーブは変更しません。

翻訳はオフラインでも使えます。ゲーム自体の言語や、追加したゲーム・スキンの名前は変更しません。ライセンス原文や開発資料は原文を保持します。コードの役割と追加方法は [開発用の構成](ARCHITECTURE.md) を参照してください。

## トレーナーカードとクイックスタート

設定のトレーナーカードには、ニックネーム・プレイ時間・参加日と、プレイ時間の多いゲームを表示します。ニックネームの初期値は「かけだしトレーナー」で、タップして30文字以内で変更できます。空欄で保存すると初期値へ戻ります。
ソフトウェアキーボードを開いたときは、入力画面を実際に見える領域へ収めます。横画面などで高さが足りない場合は、入力画面内をスクロールできます。

丸いアイコンをタップすると、16MB以下のPNG・JPEG・WebP画像を選び、プレビューを確認して保存できます。画像の中央を正方形に切り抜き、256×256のPNGへ変換してこのブラウザ内に保存します。キャンセルすると変更を破棄し、「標準に戻す」を保存すると初期アイコンへ戻ります。画像や付属メタデータを外部へ送信しません。

「ROMを更新」で引き継いだ新旧ROMは一組として時間を合算し、同じROMを二重に数えません。旧ROMを削除してもプレイ記録を残し、同じROMの再追加では元の累計から続けます。別途追加した同名ROMを自動的に同一ゲームとは扱いません。アプリが記録した実時間で、ゲーム内の時計とは別です。以前に削除されていた記録は復元できません。

新規利用では初回の保存領域作成日を参加日として記録します。既存の保存領域では、最も古いゲーム追加日を使い、記録がなければ今回の日付を保存します。過去の厳密な初回利用日を復元する仕組みではありません。ニックネーム・アイコン・参加日・プレイ記録はこのブラウザ内に保持します。「まとめてバックアップ」に含められ、復元時にプロフィールの反映を選べます。

クイックスタートは初期状態でオフです。オンにすると通常のゲーム選択で直接プレイします。「…」からは引き続き詳細を開けます。ROM未追加のゲームは再追加の案内を開き、複数選択中は起動しません。更新待ちやセーブ復旧、別タブのプレイを保護する既存の起動確認を維持します。

## 保存・復旧

ROM・セーブ・ステートの保存先は端末内のIndexedDBです。OPFSは使用していません。
共通設定と入力設定はlocalStorage、ゲーム別設定はIndexedDBのライブラリ情報、アプリ本体のオフライン保存はCache Storageを使います。
ゲームの処理は端末内で行い、ROMやセーブをアップロードするAPIはありません。
初回・未取得コア・オフライン保存・更新ではアプリのファイルを取得します。
通信プレイを開始した場合は、別途ゲームの通信データを相手と交換します。
確認した範囲と例外は `PRIVACY_AUDIT.md` に記録しています。

ゲーム内の「レポート」などは自分で行ってください。端末への自動保存はゲーム内のセーブ操作を代行しません。

| 保存の種類 | 動作・保持数 |
| --- | --- |
| ゲーム内セーブ | 自動保存が有効ならプレイ中に約2分ごとに端末へ保存。内容が変わったときは変更前のデータを最大5回分保持（容量に応じて調整） |
| 自動ステート | 自動ステート保存が有効なら約2分ごとに保存。最大5回分を保持（容量に応じて調整）。復元前や終了時などにも保存 |
| 手動ステート | 毎回新しく追加。5個までの固定スロット制ではなく、端末の空き容量の範囲で保存 |

自動記録するステート・直近のセーブ履歴・5分間隔のセーブ履歴は、それぞれ合計96 MiBを目安に制限します。
上限に収まる範囲で新しい履歴から残すため、6 MiB拡張セーブなどでは自動ステートが5件より少なくなる場合があります。
通常セーブ・自動ステートは、起動または前回の保存から約2分後に自動保存します。手動保存・バックグラウンド移行・終了時の保存は、この間隔を待ちません。
保存中は次の自動保存を積み重ねず、失敗した種類の自動再試行は2分・4分・8分・最大10分へ延期します。
中断状態だけの保存失敗では、保存できたゲーム内セーブの2分間隔は維持します。
突然のブラウザ・OS終了で最後の保存処理が実行できない場合、通常時でも最大約2分前の保存まで戻る可能性があります。保存失敗中は画面の保存状況を確認し、セーブを書き出してください。
ManicEMUの[自動ステートの120秒設定](https://github.com/Manic-EMU/ManicEMU/blob/fbaeab79c214d5920bb51afa6f2d786fb2b12a58/ManicEmu/ManicEmu/Sources/Base/Constants.swift)を参考にしています。通常セーブはWeb側の全体コピー・書込みの負担も考慮して同じ周期とし、ManicEMUの通常セーブと同じ実装を保証するものではありません。
分割できないゲーム内セーブ1件だけで96 MiBを超える場合は、その1件を保持します。
手動ステートと明示的なバックアップ復元はこの自動整理の対象外です。1件だけで上限を超える自動ステートは記録せず、ゲーム内セーブを保存し、以前の復旧データを残して失敗を表示します。
通常セーブと自動ステートの一括保存が容量不足で確実に取り消された場合は、取得済みの通常セーブだけを一度保存し直します。以前の復旧履歴は削除しません。保存結果が不明なタイムアウトなどでは再送せず、既存の保護処理を維持します。
巻き戻しは別のメモリ専用機能で、端末の保存領域には書き込みません。

「設定 → 一般」の自動ステート保存と、「設定 → セーブと保存容量」のセーブ自動保存を切り替えられます。
自動ステート保存を有効にした場合はゲーム内セーブも一緒に保存します。

ステートは、プレイ中の状態を丸ごと保存したものです。復旧用の状態が残っている場合は、
異常終了後の起動時に再開する画面が表示されます。通信中はステートを保存しません。
復旧画面の「通常どおり起動」は一覧の下に常時表示します。ステートを復元せず、ゲーム内セーブを使って通常起動できます。

メニューの「ステートを保存」は、そのまま新しい手動ステートを追加します。画面の `save` ボタンとクイック保存は、誤操作に備えて確認を残しています。
`load` は最新の手動ステートを確認して読み込み、読み込み前の状態も復旧用に残します。
「セーブステートを確認」で「手動／自動」を
切り替え、画像と日時を見て「続ける」を押すと再開できます。手動のステートを削除する場合は
「編集」で選択し、「削除」を押して確認します。旧版の3スロットも引き継ぎます。
一覧の枠は保存件数で伸縮しません。手動／自動を切り替えてもボタンの位置を保ち、
件数が多い場合は一覧内をスクロールします。枠の高さは画面サイズに合わせます。

右上の「保存済み」は、端末への保存が完了した時刻です。保存中・保存失敗もここに表示します。
詳しい保存状況は「セーブステート → 自動 → 保存状況」で確認できます。
ゲーム内セーブの履歴は、ゲーム詳細またはプレイ中の「ゲーム内セーブ・保存履歴」から復元・書き出しできます。どちらも同じ一覧を使い、整合性を確認できた履歴だけを選べます。
ゲーム内セーブは単体ファイルとしてインポート／エクスポートできます。手動ステート・復旧用の履歴は、次の一括バックアップで持ち出せます。
プレイ中のセーブ読み込みは、事前に現在の状態を退避します。保存に失敗した場合は元へ戻し、保存結果を確定できない場合や復元に失敗した場合は、再保存せずゲームを閉じて保存済みデータを保護します。
容量不足で端末への保存に失敗しても、ファイルへの書き出しは可能です。
データの破損検査や、同じゲームを複数のタブで起動させない仕組みも備えています。

**大切なセーブはファイルにも書き出してください。** 端末の故障やサイトデータの削除には
端末内のバックアップだけでは備えられません。電源断の直前まで復旧できるとは限りません。

NDSのDSVセーブはDeSmuMEの末尾情報を検証して読み込みます。元ファイルは変更しません。

ゲーム内セーブの直近5世代に加え、5分間隔・最大10世代の履歴を端末内に残します。ゲーム中の「ゲーム内セーブ・保存履歴」から復元・個別出力できます。一括バックアップにも含まれます。

mGBAの通常セーブでは、コアの保存領域への書き込みが落ち着いたことを検知し、早めに端末へ記録します。すべてのゲームの「レポート完了」を理解するものではありません。ゲーム側の保存中断やOSの突然の終了を完全には防げません。ステートの約2分間隔、通信中の保存禁止、所有権・履歴・失敗時の保護は維持します。未対応コアは従来の定期保存を使用します。

## 設定と全セーブをまとめてバックアップ

「設定 → セーブと保存容量 → まとめてバックアップ」で、書き出すゲームと内容を選び、端末内の設定・保存データをJSONへ書き出します。最新のゲーム内セーブだけに絞ることもできます。
画面は「保存／復元」で切り替えます。対象ゲームと最新セーブだけの指定は「保存する内容」で変更できます。復元前の退避データがある場合だけ、その書き出しボタンを表示します。復元後は完了画面から再読み込みします。

最新のゲーム内セーブを含めるには、先にプレイ中のゲームを終了してください。クラウド保存や自動アップロードはありません。

| 含むもの | 含まないもの |
| --- | --- |
| 全コア・GBA通信2Pを含むゲーム内セーブ、全手動ステート、直近5世代と5分間隔・最大10世代のセーブ履歴、最大5回分の自動ステート | ROM・実機BIOS、ステートのスクリーンショット |
| 共通／ゲーム別の対応設定、コア選択、キー割り当て、連射・押しっぱなし設定、チート、編集した操作配置、分類・お気に入り | カバー画像、スキン画像・ファイル・選択状態、ROMファイルそのもの |
| ROM照合用SHA-256・機種・容量、コア識別情報、ROM更新の関連・退避原本、累計プレイ記録（ゲーム名を含む） | セッション、クラッシュ診断、オフラインキャッシュ、RAM内の巻き戻し記録 |

トレーナーカードのニックネーム・プロフィール画像・参加日も含められます。復元時は別途選択します。

形式は `PalmoEMU-save-backup` バージョン2です。旧バージョン1も読み込めます。1ファイルにつき最大1000ゲーム・10000保存項目、保存データ合計128MiB、ファイル192MiBまでです。
合計が上限を超える場合は複数のファイルに分け、1つずつ書き出します。1件だけで上限を超える項目は書き出せません。ファイルは暗号化していません。セーブにはプレイヤー名などが含まれる場合があるため、個人用として保管してください。

別の端末へ復元する場合は、利用する権利のある同じROMを先に追加します。ファイル選択後に内容・ハッシュ・対応コアを検査し、
復元できるゲームを表示します。確認したゲームの保存データ・個別設定を置き換え、共通設定は「共通設定も復元する」を選んだ場合だけ反映します。ファイルを選んだだけでは変更しません。
一度登録してからROMだけ取り外したゲームも復元対象にできます。未登録のゲームは復元せず、既存のROM・カバー・ゲーム名を維持します。スキンは別途追加・選択してください。
分類・お気に入りを含むバックアップではその状態も復元します。これらの項目がない旧バックアップを読み込んだ場合は、現在の分類・お気に入りを保ちます。

すべてのタブでゲームを終了してから復元します。プレイ中のロック、破損・未対応項目、保存容量不足があれば復元を拒否します。
セーブ類は1回のIndexedDBトランザクションで置き換え、復元前のデータ・設定を端末内に1世代残します。
「復元前のバックアップを書き出す」から取り出せます。別の復元を始めると置き換わり、サイトデータを消すと失われます。同じ分割セットの続きでは、最初の復元前の状態を保持します。
設定保存の途中で処理が止まった場合は、次回起動時に保留された設定を反映してから利用を開始します。
復元前のバックアップも分割して書き出せます。iPhone実機での最大容量の処理は未検証です。

大きいデータは1ファイルあたり保存内容128MiB／JSON192MiB以内の番号付きファイルへ分割します。各ファイルを順に書き出し、復元時も全パートを取り込みます。単独の保存項目は途中で切断しません。同じパートを繰り返し取り込んでも累計時間を二重加算せず、別パートの履歴を消しません。復元前の原本は同じ分割セットの間維持します。端末全体の空き容量やブラウザのメモリ制約は残ります。

## 選択復元とステートの個別入出力

「まとめてバックアップ」の復元画面で、対象のゲームを選びます。現在の保存とファイル内の保存の最新日時を比較でき、選ばなかったゲームは変更しません。共通設定を置き換える場合だけ「共通設定も復元する」を選びます。選択したゲームの復元前データは1世代保持します。ROMを取り外したゲームにも復元できますが、プレイには同じROMの再追加が必要です。

ステート一覧で、手動保存は「編集」、自動保存は「書き出す」から1件を選んで書き出します。「ステートを取り込む」は手動一覧にあります。PalmoEMU専用のファイルを使い、ROMの内容ハッシュ・機種・容量・コア・データハッシュを検査してから、新しい手動ステートの枠へ追加します。既存の枠を上書きせず、自動で読み込みもしません。他のエミュレーターの生ステートや、異なるROMバージョンのステートは対象外です。ステートはゲーム内セーブと異なり、コア更新などで読めなくなる場合があります。ゲーム内セーブの書き出しも残してください。

## ROM更新とセーブの引き継ぎ

インポートの「ROMを更新」で更新するゲームを選び、表示された画面の「新しいROMを選ぶ」から新版のROMを指定します。ファイル選択をキャンセルしても更新画面に留まります。ゲーム詳細の「ROMを更新」からも同じ画面を開けます。ゲーム作者の案内でセーブ互換性を確認してから「引き継ぐ」を押すと、ゲーム内セーブを新版専用の保存先へコピーします。新版は通常起動し、ゲーム内の「つづきから」で確認してください。セーブステートは新版へコピーしません。

- 旧ROM・旧セーブ・ステートは変更しません。新版に保存データがある場合、プレイ中の場合、元のセーブ／コアが確認後に変わった場合は引き継ぎを中止します。
- 新版のROM・セーブ・更新前の退避データは、同じIndexedDBトランザクションで保存します。容量不足などで失敗した場合も旧版は残ります。
- 設定済みのカバー画像も引き継ぎます。新版で別の画像を選んでいる場合は、その画像を優先します。以前の更新で引き継がれなかった画像は、旧版が残り、新版が未設定または自動スクリーンショットの場合に一覧表示時に補完します。通常のROM追加や名前の一致だけでは関連付けません。
- 新版のゲーム詳細にある「前のバージョン」から旧版へ戻れます。新版の進行を旧版へ書き戻す機能ではありません。
- 「更新前のセーブを書き出す」で退避した原本を保存できます。この専用の退避データは端末内に保持し、一括バックアップv2にも含めます。旧版を残している間は、その旧版のセーブも一括バックアップの対象です。
- 同じ機種・同じコアでのコピーに限定します。容量やハッシュの検査は、ゲーム側のセーブ互換性を保証しません。更新先の作者の案内を確認してください。

「ROMだけ取り外す」はROM本体だけを削除し、ゲーム名・設定・セーブ・ステートを残します。同じ内容のROMを再追加すると元の保存先につながります。異なるバージョンのROMを代用することはできません。「ゲームを削除」は従来どおり保存データも削除する操作です。

### PokemonStartの更新通知

ファイル名からPokemonStartと版番号を識別できるゲームを登録すると、新しい配布版がある場合にライブラリとインポートへ通知します。すでに同じ版か新しい版が登録済みなら、残している旧版だけを理由に通知しません。

「確認」から公開の配布ページ・変更履歴を開き、作者の案内に従って新版ROMを作成した後、「ROMを更新」で既存の引き継ぎへ進みます。ゲーム詳細やインポートの「ROMを更新 → PokemonStartの更新を確認」からも開けます。PKSの組み込み・自動パッチ・ROMのダウンロード機能ではありません。

初期状態では、起動・復帰時などの非プレイ時にGitHubの固定APIで配布情報を確認し、アクセス制限（403/429）の場合は公式READMEの見出しと配布ファイル名を照合します。APIの制限中もREADMEで確認でき、結果を1時間保持します。同じ画面で自動確認をオフにでき、「更新を確認」で手動確認もできます。連打では再取得せず、通信失敗・アクセス制限時は間隔を空けます。オフラインや取得失敗を「最新」とは表示せず、ゲームはそのまま遊べます。閉じた通知は同じ配布情報では再表示しません。

ファイル名による版の識別は通知用の目安です。実際の引き継ぎではROMとセーブの内容を別途検査します。ネットへ送るのは固定URLの読み取り要求だけで、ROM・セーブ・登録名・ハッシュ・認証情報は送信しません。設定と取得した配布版情報はlocalStorageに保存し、バックアップには含めません。

### PokemonStartの旧セーブを変換して更新する

GBAのmGBAコアでは「ROMを更新」で新版ROMを選ぶと、ROM内の保存バージョンと「つづきから」の最低対応版を読み取り、セーブの内容と照合します。**更新先ROMが読み込める最低バージョンより古いセーブを引き継ぐときに、必要な変換を行います。** 更新先を0.42.3など特定の版番号・CRCの一覧に限定しません。0.35.0→0.42.5でも「セーブデータを変換して更新」を押すだけで適用でき、ダウンロードと再インポートは不要です。

くりーぱー作の提供ツール1.0.9を組み込み、**0.49.0までの版情報**を扱います。新しい技・持ち物の上限検査も修正しました。変換が必要な場合は、保存領域・暗号化・ゲーム内変数を隣接する版ごとに変換します。実際のROMが読み込める範囲内で、再開補正まで確認できた定義を中間出力に選びます（現在は最大0.42.5）。版番号だけを最新に書き換えてゲーム側の更新を飛ばさず、その後の処理を新版ROMに任せます。互換なセーブはそのまま引き継ぎ、未確認の保存形式や逆方向の更新は拒否します。[PokemonStart](https://github.com/pm-start/PokemonStart)の開発・協力として[onikoro334274-cell](https://github.com/onikoro334274-cell)と[liru55](https://github.com/liru55)を別途クレジットしています。

確認した0.42.3／0.42.5のROM内の最低対応版は0.36.2です。[作者の変更履歴](https://github.com/pm-start/PokemonStart/blob/a9848a797893f909d7f2c50f3bc4ea5ce71fc804/CHANGELOG.md)も0.42.4・0.42.5で0.38.x以降をそのまま使えると案内しています。

0.49.0の実ROMも既存の判定器で認識し、最低対応版0.36.2、上限0.49.0を確認しました（ゲームプレイや新しいIDの全件検査ではありません）。確認範囲は `scripts/start-save-migrate/ROM_REVIEW.md` に記録しています。

0.47.1で確認した、上下限を別の関数で判定する処理にも対応しています。提供されたROMの最低対応版は0.36.2、上限は0.47.1でした。0.40.0のセーブは構造検査に通れば変換せずコピーします。未知の判定処理や矛盾した上下限を無条件に許可することはありません。

| 条件 | 操作 |
| --- | --- |
| 元のセーブが更新先ROMの最低対応版より古く、提供ツールが変換できる | 変換して更新。0.35.0→0.42.5も対象です。 |
| 元のセーブが更新先ROMの対応範囲内で、保存形式の検査も成功 | 変換せず、両スロット・時計情報を含めバイト列をそのままコピーします。 |
| セーブに記録されたバージョンが更新先ROMより新しい | 引き継ぎ・変換を止めます。「未確認」の承認では続行できません。旧版を遊ぶ場合は、更新前に残した旧セーブを使います。 |
| 更新先の判定処理を読めない、変換器の中間形式を新版が読めない、セーブの構造が一致しない | 適用を止めます。通常コピーへの自動迂回はしません。 |

- セーブに記録された版を優先し、記録がない旧版ではROM照合・ファイル名から候補を選びます。変換直後にさらにROMを更新しても、まだゲーム内保存されていない中間形式を正しく判別します。手動で版を変えた場合も内部版・ボックス数・暗号化を照合します。
- 原本を退避し、変換結果・ROM・カバー画像をまとめて保存します。既に追加した新版への適用も、現在のセーブをバックアップへ残してから行います。旧ROM・旧セーブ・手動ステートは削除しません。
- **以前の単純コピーで更新に失敗した場合**は、新版の「ROMを更新」で同じ新版ROMを選び直すと、更新前のバックアップから変換できます。「ROMを更新 → 詳細 → PokemonStartのセーブを変換」からも選べます。
- ROMの識別と変換は端末内のWorkerで実行します。ROM・セーブ・名前は送信しません。対象はPokemonStartの通常セーブ（128KiB・1MiB・6MiB、16バイトの時計情報を含む）です。ステートや他のゲームの変換には使えません。
- 判定処理が同じ新版は、そのROMに書かれた境界を使います。未知の保存構造・ゲーム内テーブル変更まで対応を保証するものではありません。解析できないROMは止めます。既知のCRCだけで識別した旧ROMには、確認済みの変更履歴に基づく補助判定を使います。
- インポート後は旧版の自動復旧データを無効にします。起動後は古いステートを使わず、ゲーム内の「つづきから」で確認してください。

合成セーブで両スロット・時計情報・原本・バックアップの保持と実際の更新画面を検証しています。利用者のセーブや長期のゲーム進行、iPhone実機での今回の更新は未検証です。[出典と変更内容](vendor/start-save-migrate/README.md)を記載しています。

## 互換性補正

PokemonStartの未使用セーブ領域を誤判定する処理を補正します。版番号やROM全体のハッシュで限定せず、問題の判定処理を構造から検出します。同じ処理なら、ROMの更新で配置や無関係な内容が変わっても自動的に補正できます。[ROM更新時に必要に応じて行う旧セーブの形式変換](#pokemonstartの旧セーブを変換して更新する)とは別の機能です。

拡張カートリッジの署名、比較する保存領域、16バイトの比較と読込み処理、呼び出し関係を確認します。対象が一意に決まり、mGBA Celioが6MiBの保存領域に対応する場合だけ実行用のコピーを補正します。似た命令だけの一致、複数候補、別用途との共有、既に補正済みの処理には適用しません。将来、判定処理そのものが変わった場合は別途確認が必要です。

「ぼうけんのしょ2を使うには最新のmGBAを使ってください」という表示は、独立した領域の内容が同じ（未使用で空など）でも非対応と判定する場合に出ます。セーブ変換は保存形式の移行、ここでの補正は起動時の機能判定への対応です。移行済みセーブの再変換は不要です。

元のROMファイル・端末内に保存したROM・保存先の識別子は変えません。認識のためにセーブへ印を書き込む処理も追加していません。判定構造を確認できないROMは変更せず、ROM・セーブの送信や同梱も行いません。

更新後はゲームを一度終了し、ゲーム内セーブから起動し直してください。古いステートには補正前の判定結果が残る場合があります。既存のステートは削除しません。

0.40.0の検証用に作成したセーブでは、冒険の書1を残して2を作成・保存し、両方から再開できることを確認しました。0.42.3は判定関数を合成の保存領域で分離検証しています。利用者の既存セーブ、0.42.3での実際の進行、長期の進行、実機iPhoneは未検証です。[検証記録](RELEASE_VALIDATION.md)に範囲を記載しています。

## スキンとレイアウト編集

「設定 → スキン」で機種共通のスキンを選べます。
GB・GBC・GBA・FC・SFC・MD・NDSでは、従来の「標準」に加えて「ManicEMU」も選べます。既存の選択は変更しません。同梱版はオフライン保存の対象です。
ゲームごとの指定は、ライブラリの「… → スキン設定」またはプレイ中のメニューから変更できます。
「機種の設定を使う」を選ぶと共通設定に戻ります。ゲーム別の指定は再起動後も保持されます。
追加したスキンはプレビュー付きの一覧に残り、標準色に変えた後も選び直せます。
上部の「縦画面」「横画面」を切り替えて、それぞれ別のスキンを選べます。標準の色も向き別に保存します。
ゲーム別の「機種の設定を使う」も向き別です。端末を回転すると対応するスキンへ切り替わります。
以前の共通設定は両方の向きに引き継ぎ、片方を変更してももう片方は保持します。
最後に見ていた機種も保持します。削除は「編集」から選び、確認後に行います。

対応する全機種に専用スキンがあります。「機種標準」の配色に加え、パープル・グラファイト・
ミント・サンセットの4色を選べます。既存の色指定・配置設定は引き継ぎ、未指定時は機種標準になります。

| 機種 | 標準デザインとボタン構成 |
| --- | --- |
| GB | グレーと深い赤、斜めのA/B、十字キー、SELECT/START |
| GBC | クリアケース風、斜めのA/B、十字キー、SELECT/START |
| GBA | 丸みのあるワイド携帯機風、斜めのA/B、独立したL/R |
| FC | クリーム色と赤、横並びのB/A、SELECT/START |
| SFC | グレーの本体、青X・緑Y・赤A・黄Bのひし形配置、L/R |
| MD | ダーク本体、上段の小さいX/Y/Zと下段の大きいA/B/C、MODE/START |
| NDS | ダーク本体、上下／大小の2画面、ABXYとL/R |

標準スキンの十字キーは、見た目のサイズと別に反応範囲を調整できます。4方向／8方向・中央の無反応範囲・斜めの入りやすさは[入力の調整と追加操作](#入力の調整と追加操作)を参照してください。
「標準」スキンの画像はオリジナルのSVGです。画面の広さとノッチなどの余白に合わせ、
ボタンを下または左右に配置します。ゲーム画面の比率は保ち、回転やウィンドウのサイズ変更にも追従します。
プレビューも使用中の画面比率に合わせます。メニューやライブラリは表示幅に応じて折り返します。
「画面・ボタンのレイアウト」はManicEMUの「画面／ボタン」切替と移動・拡縮操作を参考にしています。
画面と各ボタンをドラッグして移動し、サイズスライダー・丸いハンドル・2本指のピンチで大きさを変更できます。
縦横比を維持し、画面外へはみ出さない範囲で調整します。ボタンは個別／まとめてサイズ・透明度を変更できます。
画面はボタンの背面に描画します。ボタンを画面に重ねても操作でき、透明度（0〜80%）は編集・プレビュー・プレイで共通です。
配置編集にはグリッドと吸着を用意しています。間隔は3段階で、中央線・端・ほかの対象の端や中心・左右対称の位置へ
近づけるとガイドを表示して吸着します。「横中央」「縦中央」、基準を選ぶ「高さをそろえる」「左右対称にする」でも整えられます。
左右対称は基準と同じ高さで中央線の反対側へ移動します。サイズは変えず、画面内に収まる範囲で位置を合わせます。
吸着をオフにすると自由に配置できます。キーボードの矢印キーやAltを押しながらのドラッグも吸着せず微調整できます。
グリッドとガイドは編集画面だけに表示され、プレイ画面には出ません。
「初期配置に戻す」は編集中の向きの画面とボタンを戻します。保存前ならキャンセルで変更を破棄できます。
NDSは「画面」の選択欄でメイン画面／サブ画面を個別に調整できます。画面切り替え時は表示内容と
タッチ入力が一緒に移動します。従来の2画面まとめての配置設定も保持します。画面だけの配置指定は
コントロール非表示時にも適用され、未指定時は2画面の表示領域を広げます。
縦・横の配置は別々に保存します。ゲーム別・機種共通の設定に対応し、標準スキンの全配色で共有します。
「保存」で確定します。保存したボタン位置は自動配置より優先します。
同梱ManicEMUスキンと外部スキンは作者の配置を保ったまま画面に収めます。配置編集は「標準」スキンで利用できます。
サイズは標準配置を100%とし、ボタンは50〜200%、画面は25〜200%の範囲で変更できます。
画面内に収まる大きさが上限なので、端末や対象によっては200%まで拡大できません。
キーボードでは選択対象を矢印キーで移動でき、サイズ変更ハンドルにフォーカスすると矢印キーで拡縮できます。
メニューの「画面ボタン」をオフにするとボタンを隠せます。画面の配置を指定していない場合は、表示領域を広げます。
端末内の `.deltaskin` / `.manicskin` も追加できます。
PNG・JPEG・WebP・PDF、機種別・端末別の配置、複数画面と切り抜き、NDSのタッチ入力、
クイック保存・読込・早送り、可動スティック、Manicのボタン画像・押下アニメーションに対応しています。
色補正・ぼかし・発光・回転などはブラウザで再現します。Core Imageと完全に同じ描画ではありません。
未対応の効果・操作とCAF効果音は、取り込み後に注意点を表示します。
ファイルは40MiB以下、展開後100MiB以下です。対応範囲と検証内容は [SKIN_COMPATIBILITY.md](SKIN_COMPATIBILITY.md) を参照してください。
追加したスキンはサーバーへ送信しません。作者の利用条件に従って使用してください。

## コントローラー・連射・押しっぱなし

設定またはゲームメニューの「コントローラー・キーボード」を開きます。
「ボタン割り当て」で機種と入力機器を選び、変更したい操作を押してから実際のキー・ゲームパッドのボタンや軸を入力します。
キーボード、ゲームパッド共通、ブラウザが識別する接続中のゲームパッド別に保存し、同じ機種のゲームで使用します。
同じ種類のゲームパッドをブラウザが同じIDで報告する場合は、同じ設定を使います。個別設定のないパッドは共通設定を使います。
割り当ての解除、入力待ちのキャンセル、選択した機種／入力機器の初期化ができます。

ゲームの各ボタンに加え、メニュー・ステート保存・クイックロード・速度切り替え・巻き戻しを割り当てられます。
標準キーは矢印、X/Z、Enter/Shift、対応機種ではA/S・W/Q等。特殊操作はEsc、F5、F8、Tab、Rです。
保存・ロードでは既存の確認画面を使い、巻き戻しは対応機種で記録がある場合だけ動きます。

「連射・押しっぱなし」では、各ボタンを通常／連射／押しっぱなし／両方から選びます。
連射周期は50〜1000ms（8段階、初期値100ms）。タッチ・キーボード・ゲームパッドに共通して適用します。
押しっぱなしは1回押して固定し、もう1回押すと解除します。一時停止、タブの非表示・フォーカス喪失、
入力機器の切断、ゲームの終了などでも解除します。通信中は操作補助とメニュー以外の特殊操作を停止します。
ManicEMUのTriggerProのマクロ編集・条件分岐・複数操作の自動実行を移植した機能ではありません。

NES・SNES・メガドライブは、標準コアとjgenesisで1P／2Pを使えます。コントローラー設定で画面ボタン・キーボード・接続パッドを割り当てます。連射・押しっぱなし設定は1Pに適用します。

## 入力の調整と追加操作

「コントローラーと操作補助」では、ROMを起動せずに入力をテストし、標準スキンの十字キーの4方向／8方向、中央の無反応範囲、斜めの入りやすさ、タッチ範囲を調整できます。見た目の位置・サイズとは別の設定です。追加したスキンは作者の操作範囲を維持します。ゲーム詳細から変更するとゲーム別に保存し、共通設定へ戻す操作も使えます。

DSの操作設定で「ふたを閉じる／開く」を使えます。DeSmuME 2015とmelonDSの実際のふた状態へ接続します。実機の磁気センサーや端末カバーを使用する機能ではありません。ステート読込時、DeSmuMEは保存時のふた状態を復元し、melonDSは読込時のふた位置を維持します。既存コアの保存形式は変更していません。

GB／GBCはmGBAコアで端末内の2台通信を使えます。同じROMを2台分起動し、1P／2Pを切り替えて操作します。2Pのセーブは別に保存し、手元の別セーブも選べます。異なるROM同士の接続には対応しません。両方のゲームで通信を終えてゲーム内でセーブし、「両方のセーブを確定して終了」を選んで確認します。中止・バックグラウンド移動では開始前へ戻し、2Pの既存セーブを保護します。オンライン・USB通信はGB／GBCには対応しません。通信中は巻き戻し・ステート読み込みを使えません。

## タッチ操作

指を離した通知を取り逃がしても、全指の接触終了や次の最初のタッチで残った入力を解除します。標準・ManicEMU同梱・追加スキンで共通の処理を使います。長押し・同時押し・通信番号などの入力操作は維持します。ホーム・インポート・設定でも意図しないダブルタップ拡大を抑え、通常のスクロール・文字編集・ピンチ拡大は維持します。

ゲーム中はプレイヤーとルートの`overscroll-behavior`で引っ張り更新・スクロール伝播を抑止します。ゲームを閉じると通常の設定に戻り、通信欄の縦スクロール・選択・コピー・貼り付けは維持します。OSの戻る操作や拡大補助は無効化しません。Android/iPhone実機での確認とは区別した[調査・検証範囲](MOBILE_INPUT_REVIEW.md)を参照してください。

## タッチの振動

Vibration APIがあるブラウザで、画面ボタンを押すと8ms／20msの振動を要求します。
非対応ブラウザでは設定を無効にし、非対応と表示します。iPhone Safariは非対応です。
Android Chrome系でも、振動モーターやOS設定に左右されます。ブラウザAPIの呼び出し成功は実際の振動を保証しません。

## NDS（iPhone向け実験版）

`.nds` をインポートすると、NDS専用のダークスキンで起動します。縦向きは同じ大きさの2画面を上下に並べ、
操作部を下にまとめます。横向きは左に大きいメイン画面、右上にサブ画面、右下にABXYなどを配置し、
十字キーとLはメイン画面に重ねます。2画面とも4:3を維持し、下画面に直接タッチできます。
「画面切り替え」で2画面の位置を入れ替えられます。A/B/X/Y、L/R、START/SELECTに対応します。
DeSmuMEの省電力モードは初期状態でオンです。ゲームの内部速度を保ちつつ描画を約30fpsに抑えます。
ゲームメニューでオフにすると通常の描画頻度になります。重い場合は映像フィルターをピクセルにしてください。

ゲーム内セーブの自動保存とインポート／エクスポート、最大5回分のバックアップ・自動ステート、
端末内の手動ステート保存・再開に対応します。PalmoEMU専用形式でのステート単体のインポート／エクスポートと、設定・セーブをまとめたバックアップにも対応します。
DeSmuMEはHLE、melonDSはBSDライセンスのFreeBIOSを使って直接起動します。市販機から抽出したBIOSは同梱しません。
ダークスキンの縁のアクセントは機種標準＋4色から選べます。外部NDSスキンにも対応しています。DSi、Wi-Fi通信、実マイク入力は未対応です。
ROMの受付上限は512MiBですが、大きいROMはiPhoneのメモリ上限で起動できない場合があります。
自作テストプログラムでWindowsのEdge / WebKitを検証済みです。市販ゲームの互換性、
iPhone実機の速度・発熱は未検証です。

- **DSの操作**：ゲーム中のメニューから「息を吹く（5秒）」を選ぶと、ゲームへ戻り疑似入力を送ります。実際のマイクは使いません。一時停止・再起動・ステート読込・終了で停止します。DeSmuMEとmelonDSに対応する実装です。
- **DS本体の言語**：日本語・英語・フランス語・ドイツ語・イタリア語・スペイン語から選択できます。ゲームを終了して開き直すと反映します。「コアの初期設定」は従来の動作を維持します。アプリの表示言語とは別です。
- 「ふたを閉じる／開く」も使えます。[入力の調整と追加操作](#入力の調整と追加操作)を参照してください。

## カートリッジ設定

mGBAのGBAカートリッジ設定で、傾き・回転・太陽センサーとCPU速度を変更できます。端末の動きは許可した場合だけ使用し、スライダーでも操作できます。CPU速度の初期値は「自動」です。通常のROMは1倍、PokemonStartの拡張カートリッジ署名を検出したROMは参照元と同じ2倍を使用します。ファイル名や版番号には依存しません。手動で選んだ速度は維持し、通信中は1倍固定です。これはゲーム全体の倍速設定とは別です。

**GB/GBCの傾き**：mGBAの「カートリッジ」から、対応ゲームの傾きセンサーをスライダーか端末の動きで操作します。GBA専用のCPU速度・太陽・ジャイロ設定は表示しません。

**時計**：mGBAで対応ゲームの時刻を端末の時計から最大10年ずらせます。初期値は端末と同じです。ゲーム別設定として保存し、ステート読込・再起動後も選んだ設定を適用します。ゲームの時間連動イベントに影響する場合があります。

**ゲームの振動**：mGBAで初期値オフ。対応ゲームが出す振動を、最後に操作した1Pの対応ゲームパッドへ送ります。ブラウザ・機器側の振動APIが必要です。タッチ操作時の振動設定とは別です。一時停止・非表示・切断・終了で止めます。

## 巻き戻し

ゲーム詳細またはゲームメニューで「巻き戻しを記録」をオンにすると、プレイ中の状態をRAMに記録します。
初期状態はオフです。メニューの「最大3秒戻す」、割り当てた入力、対応スキンの巻き戻し操作で、残っている記録の範囲へ戻ります。
記録はゲーム内時間の約0.5秒ごと、最大10秒・21件です。メモリ上限に達したら古い記録を捨てるため、戻せる時間は短くなる場合があります。

対象はGB/GBCのmGBA・jgenesisと、GBAのmGBA・VBA-Nextです。NDS・FC・SFC・MD・3DSは対象外です。
保持する履歴と失敗時の復元用コピーは合計8MiBまでで、1状態が4MiBを超える場合は安全に復元できないため記録を停止します。
コアが状態を書き出す際の一時メモリはこの保持上限とは別です。大きな拡張RAM／拡張セーブを使うROMでは利用できない場合があります。

CPU等の状態と、その時点のゲーム内セーブRAMを一緒に戻します。巻き戻しの操作自体では、端末の永続セーブを書き換えません。
復元中は入力・保存処理を止めます。再開後は通常の自動保存・終了時保存が行われるので、以前の進行も残したい場合は先に書き出してください。
ゲーム・コアの変更、ステートの読み込み、リセット、セーブのインポート、チート変更、コアエラー、通信開始で記録を消します。
記録は一時メモリだけで、終了・再読込・バックアップの対象には残りません。通信中は利用できません。

## フィルターとコア最適化

映像フィルターは「ピクセル」「なめらか」「スキャンライン」「輪郭補正2倍」「輪郭補正4倍（高品質）」「LCD」「CRT」「xBRZ」から選べます。LCD／CRTは効果の強さも調整できます。GPUを使う効果が利用できない場合はピクセル表示になります。負荷が大きいときは「ピクセル」に戻してください。

コアにはCelio Web由来の音声・描画処理の最適化を取り込んでいます。詳細は[機能移植の確認記録](FEATURE_REVIEW.md)を参照してください。全ゲーム・全端末で同じ速度になることを保証するものではありません。

ゲーム内セーブの比較で不要なコピーを避け、大きな保存データの読み書きは端末内のWorkerへ移します。保存中の操作の引っかかりを減らしつつ、全バイトの確認・履歴・失敗時の保護を維持します。GBAは等速時に約60fpsで動作し、120Hzの画面でもゲームを倍速で実行することはありません。新しいゲーム映像ができたときだけ、ブラウザの描画タイミングで表示します。

mGBAの起動時に自作の空ループROMと合成ピクセルで転送方法を短時間比較します。利用者のROMやセーブは使いません。計測できない場合は従来の行単位転送に戻します。LCD/CRTの効果の強さも調整できます。

## ゲーム映像の撮影

プレイ画面のカメラボタンから「スクリーンショット」を選ぶと、撮影したゲーム映像のプレビューを表示します。「画像を保存」でPNGファイルのダウンロードを開始し、ファイル共有に対応するブラウザでは「共有」から端末の共有メニューを開けます。撮影しただけではダウンロードを開始せず、保存や共有をキャンセルしてもプレビューからやり直せます。スキン・ボタン・FPS・保存状況は画像に含めません。DSでは上下のゲーム画面をまとめて撮影します。従来のメニュー内の「スクリーンショット」は直接撮影します。

プレビューを開いてもゲームは動き続けます。閉じるボタンでプレビューを片付け、一時停止中も撮影できます。ゲームを終了すると撮影プレビューを消去します。

画像名は「ゲーム名_年-月-日_時-分-秒.png」です。撮影した端末の日時を使い、同じ秒の連続撮影には連番を加えます。同じ画像の保存や共有をやり直す場合は名前を維持します。PNGはゲーム映像を劣化なく保存し、GBAの通常表示は240×160です。輪郭補正などを使用した場合は補正後の映像を保存しますが、元のゲームにない細部が増えるわけではありません。

表示は「映像とフレームレート」の「スクリーンショットボタン」で切り替えます。ゲーム別設定にも対応します。位置・サイズ・透明度は「スキン」の配置編集から変更し、縦横別・機種共通またはゲーム別に保存できます。取り込んだスキンでは、この共通スクリーンショットボタンだけを配置編集できます。プレイ画面ではボタンを長押しして、そのままドラッグして移動できます。離すと、そのゲームの現在の向きの配置として保存します。短いタップでスクリーンショット／録画を選びます。録画中はタップすると録画を停止します。

アプリから画像を自動送信することはありません。「共有」を選ぶと、端末の共有メニューで指定した保存先や送信先に画像を渡します。「画像を保存」の保存先やダウンロード時の表示はブラウザに従い、写真アプリへ保存する場合は対応端末の共有メニューを使います。


### ゲーム音付きの動画録画

カメラボタンの「録画を開始」でゲーム映像とゲーム音を録画します。常設ボタンは増やさず、録画中は同じカメラボタンに赤い停止マークと経過時間を表示します。もう一度タップするとゲームを先に一時停止し、「動画を準備しています…」を表示して録画の終了処理を待ちます。完了後は動画を再生確認できます。「動画を保存」でファイルへ書き出し、対応端末では「共有」から写真・ファイルなどの保存先を選べます。共有をキャンセルしても再操作できます。閉じる前には録画を破棄する確認を表示します。

iPhone Safariを想定し、対応形式を調べてMP4（H.264/AAC）を優先します。AAC音声を録音できない場合やMP4を開始できないブラウザでは、対応するWebMを使います。非対応環境では録画だけを無効にし、スクリーンショットは引き続き利用できます。動画は最大30fps・長辺720px、上限は5分または64MiBです。長辺360px以下の画面は補間せず2倍に拡大してから圧縮し、GBAは480×320pxになります。映像4Mbps・音声128kbpsを要求しますが、実際のビットレートはブラウザや映像によって変わります。元の画面にない細部が増えるわけではありません。容量上限に近づくと、終了処理用の余白を残して自動停止します。音量・ミュート・倍速時の音はゲームの現在の設定に従い、マイクは使いません。スキンや操作ボタンは含めず、NDSは上下2画面を縦にまとめます。向きを変えても録画サイズは変わりません。

メニューによる一時停止、画面を離れたとき、コアの切り替えやゲーム終了では録画を停止します。ゲーム終了後も動画プレビューを残します。録画結果を閉じるまでは自動更新を保留し、再読み込み時に確認を出しますが、録画はメモリ内だけに保持します。OSによるアプリ終了からの復旧や、録画のバックアップはありません。必要な動画はファイルへ保存してください。

動画名は「ゲーム名_年-月-日_時-分-秒.mp4」（WebMは`.webm`）です。同じ秒の連続録画には連番も加えます。iPhone・iPadの「動画を保存」は、ファイル共有に対応していれば標準の保存・共有シートを開きます。「ビデオを保存」「ファイルに保存」など、端末が提示する保存先を選んでください。キャンセルや失敗でもゲームと動画を保持し、ダウンロードへの自動切替はしません。OS側で選んだ操作の完了はページから確認できないため、「保存しました」とは表示しません。

保存先へ直接書き込めるブラウザでは、書き込み完了後だけ「保存しました」と表示します。それ以外は通常のダウンロードを使い、「ダウンロード一覧を確認」と表示します。この経路はページから保存完了を検知できません。ダウンロードが別画面で開かれる場合もゲームのタブを置き換えず、動画プレビューを閉じるまでURLを保持します。画面のキャッシュから戻った場合も、ゲーム・録画・保存処理が残っている間はアプリの再読み込みを保留します。OSがページ自体を終了した場合の保持は保証できません。

検証はPC版Edgeで実際に録画・再生し、ゲーム音が含まれることを確認しています。Windows版テスト用WebKitは録画APIがないため、非対応時のUIと模擬APIによる状態遷移を検査しています。iPhone実機での録画・写真への保存・負荷は未検証です。

## GBA通信（Beta）

Celio方式に対応するGBAゲーム用です。すべてのGBAゲームに対応する機能ではありません。
通信パネルで次の3方式を選べます。

- オンライン：部屋番号で相手と接続。
- この端末で2台：同じROMをもう1台起動し、1P／2Pを切り替え。2Pは専用の保存領域を使い、前回のセーブ・ファイル・最初からを選べます。
- USB実機：PCのChrome / EdgeでWeb Serial対応のCelio変換器を選択。対応する実機通信ケーブルも必要です。iPhoneのSafariはUSB接続に非対応です。USB切断・中止で戻せるのはブラウザ側だけで、実機のセーブは復元できません。

端末内・USB通信では中継サーバーへ接続しません。端末内通信のセーブは正常終了時に2人分を1つのトランザクションで保存します。
中止時は1Pを通信前に戻し、保存済みの2Pデータは置き換えません。2Pセーブは通信パネルからファイルに書き出せます。
2台分のCPUとメモリを使うため、iPhone実機の速度やメモリ使用量は別途確認が必要です。USB実機との交換・対戦も未検証です。

ゲーム画面の上中央のWi-Fiボタン、またはゲームメニューの「通信」から開きます。
通信パネルを開いたままゲームを操作できます。パネル上部をドラッグして移動でき、
閉じても通信は続きます。部屋番号は欄内のコピーボタンでコピーできます。
パネル上部はWi-Fiマークと薄い「Beta」表記です。
Wi-Fiマークは待機中が黄色、接続中が緑です。パネルの「×」は非表示、「通信を中止」は接続終了です。

1. 一方が「部屋を作る」を押し、4桁の番号を相手に伝えます。
2. 相手が番号を入力して「参加」を押します。
3. 両方のゲームでケーブル通信の受付へ進みます。

旧形式のCelioサーバーでは、liru55 / mgba-celio-webの固定版との相互接続を確認しています。
新形式のサーバーでは、本版同士で通信できます。相手も同じ通信形式への対応が必要です。
両形式を自動判別し、新形式のまとめ送信・受信確認・再送に対応します。人数は2人です。
対象バージョンと検査条件は LINK_COMPATIBILITY.md を参照してください。
実際のゲームで交換・対戦が完了することは未検証です。

オンライン通信を明示的に始めた場合だけ celio-server.up.railway.app へ接続します。
ROM・セーブファイルは送りませんが、ゲームの通信データはサーバー経由で相手に届きます。
サーバー側にはIPアドレスも伝わります。部屋番号にパスワード認証はありません。

通信前の状態を端末内へ保存します。通信中は1倍速に固定し、チート・セーブの自動保存・
ステート操作を止めます。ゲーム内で通信が正常終了すると結果を保存し、中止・切断時は
通信前へ戻します。ゲーム内の通信開始後に別のタブやアプリへ移ると切断します。
0.3.36ではオンラインの部屋番号を共有する間、相手が参加しても画面へ戻るまで通信開始を保留します。復帰後は一時停止画面から再開してください。端末がブラウザを停止した場合やサーバーが接続を切った場合は、部屋を作り直す必要があります。部屋待機中も通信開始前のバックアップを保持します。

## オフライン

「設定 → オフラインで使う → オフライン用に準備」で、追加済みゲームのコアと現在の設定に必要なファイルを保存できます。同梱スキンは画面比率で選び、縦横の両方を準備します。端末名だけで画像を除外しません。
コア・スキン・画面サイズを変更した場合は再度準備してください。「詳細 → すべてのファイルを保存」も使えます。保存済みのファイルは自動削除しません。以前に全体を保存した端末が、この操作だけで必要分へ縮小するわけではありません。完了後はネットに接続せず遊べます。ROMはあらかじめライブラリに追加してください。
GBA通信にはネット接続が必要です。

## 起動・更新

Node.jsを用意し、`web` フォルダーで `node scripts/serve.cjs` を実行します。
リポジトリのルートからは `node web/scripts/serve.cjs` です。既定URLは `http://127.0.0.1:4173/`。
通常の起動に `npm install` やコアの再ビルドは不要です。
開発サーバーは `127.0.0.1` に限定して待ち受けます。iPhoneからこのPCのループバックURLには接続できません。
iPhoneで使う場合は、端末からアクセスできるHTTPSの配信先を用意してください。

初めて開く場合は、その時点の公開版を読み込むため、更新操作は不要です。
更新が見つかり、プレイや保存・取り込み・編集をしていなければ、画面中央に「アプリの更新」を表示します。「ダウンロード中…」から「更新中…」へ進み、すべてのタブが安全に切り替えられる状態になると自動で反映します。
「プレイ」やROM更新後の「新版をプレイ」を押した際にアプリの更新が入った場合は、更新完了後に選んだゲームを一度だけ起動します。待機中に「今は続ける」を選んだ場合も、そのゲームの起動へ進みます。完了済みのROM更新・セーブ引き継ぎをやり直す必要はありません。更新内容の案内はゲーム終了後に表示します。
プレイ中・通信中・設定の編集中・ファイル選択中には再読込しません。
旧版や応答のないタブなど、安全を確認できない画面が残っている場合は待機します。
すべてのタブを閉じた後の切り替えと、手動更新も引き続き利用できます。
自動切り替え中は「更新中…」と回転アイコンを約1.2秒以上表示し、切り替え後に「更新しました」と通知します。動きを減らす設定ではアイコンを静止させます。
オフライン中は今の版を使います。更新・オフライン保存の一時的な取得失敗は、対象ファイルを最大3回試します。更新の取得が復旧したら、安全に切り替えられる状態で自動反映します。「あとで」「今は続ける」を選んだ場合は、その訪問中の自動反映を保留します。
ダウンロードが60秒続くと「今は続ける」を表示しますが、経過時間だけで失敗にはしません。取得に失敗しても、現在の版とROM・セーブは保持します。
更新では、端末にあるファイルの内容を確認し、変更・不足分だけを取得します。アプリ本体と取得済みのコア・スキンを引き継ぎ、未使用で変更もない資産は使用時に取得します。全体をオフライン保存済みの場合は、その範囲を維持します。
従来方式からの初回移行は、旧版の構成記録がないため全体を対象にしますが、一致するファイルは端末内で再利用します。初回移行後も、すでに全体を保存済みの端末は全体のオフライン利用を維持します。通信量と所要時間は、変更内容・保存済みデータ・回線・端末によって変わります。
対応する版ではダウンロード画面に準備済み容量の割合を表示します。空き容量不足は通信エラーと区別し、自動確認を30分間抑えます。容量を確保した後は手動更新ですぐ再試行できます。空き容量の推定値だけを理由に、ROM・セーブ・旧版の資産を削除しません。
すぐ反映したい場合は、ゲームを保存して終了し、「設定」→「アプリの更新」を開きます。
更新画面以外のアプリのタブを閉じて「更新」を押してください。ROM・セーブ・ステートは引き継がれます。
**サイトデータは削除しないでください。**

更新・プライバシー・ライセンスの各ページの「戻る」で設定画面へ戻れます。

## クラッシュ診断

「設定 → クラッシュ診断」から、エラー記録と現在の環境情報をJSONファイルに書き出せます。
記録は初期状態でオンで、直近5件を端末のlocalStorageに保存します。オフにする、記録だけ削除する、書き出す内容を事前に確認する操作もできます。
記録するのは日時、アプリの版、ブラウザ・OSの種類、使用コア、処理の状態、エラーの種類、アプリ内の発生箇所などです。ROM・セーブ・ゲーム名・生のエラーメッセージ・メモリの中身は含めず、自動送信もしません。保存できない場合は、そのタブ内だけで保持します。
メモリ確保の失敗には、処理の用途（ROM読み込み・セーブ取り込み・ステート取り込み・チート設定）、確保要求のバイト数、処理直前のWasm線形メモリ容量、ROMのサイズ区分を追加します。確保処理が0を返した場合と例外を投げた場合、mGBAの内部初期化が失敗を返した場合を区別します。内部初期化のどの確保が失敗したかは現行コアから取得できないため、その要求サイズは`null`とし、ROM容量で代用しません。これだけでブラウザのメモリ拡張が拒否された理由や、端末全体の空きメモリを特定できるわけではありません。
ROM取り込みの失敗は例外名に加えて処理段階とサイズ区分を記録し、コアの確保失敗とは区別します。ZIPの圧縮後サイズをROM容量とは扱わず、サイズ区分は不明とします。追加情報も端末内の直近5件に限り、記録オフ・削除・手動書き出しの設定に従います。
ブラウザごと終了した瞬間の詳細や、OSが出力するメモリダンプは取得できません。前回のプレイが正常終了していなかった場合は、次回プレイ開始時にその事実を記録します。セーブの復旧は既存のバックアップ機能を使います。

## 変更後の生成ファイル

以下は `web` フォルダーで実行します。Node.jsとPython 3が必要です。
`build-offline.cjs` は先に翻訳を自動更新します。新しい文言の生成には [翻訳用の初回準備](LOCALIZATION_REVIEW.md#開発pcの初回準備) が必要です。変更通知は日本語の `changes` だけを追加・編集できます。自動生成は下書きとし、担当エージェントが追加・変更した文言を全8翻訳言語で校正してください。校正後に再生成・整合性検査・対象画面の確認を行い、結果を記録してからコミット・pushへ進みます。詳しくは [差分校正の手順](LOCALIZATION_REVIEW.md#文言変更通知の更新) を参照してください。
開発中は `npm run dev` が変更を監視し、同じ生成処理を実行します。`npm run i18n:sync` で翻訳だけ、`npm run i18n:check` で検査だけを実行できます。
macOS / Linuxでは、例の `python` を `python3` に読み替えてください。

```sh
node scripts/build-offline.cjs
```

`offline-manifest.js` はオフライン対象と更新識別用のハッシュ、
`sources/web-ui-source.zip` は配布するWeb実装のソースです。このZIPはGitへ含めず、
`prepare-release.py` が検証・公開するコミットのファイルから配布用フォルダー内に生成します。
ローカルに古いZIPが残っていても取り込みません。固定したコアのソースアーカイブは従来どおりGitで管理します。
UIやREADMEを変更した後もオフラインマニフェストを再生成してください。`build-offline.cjs --check` は書き換えずに整合性を検査します。

配布内容の記録は確認後に更新します。次はリポジトリのルートから実行します。
`prepare-release.py` は `work/release` の専用コピーと対応ソースZIPを作り直します。
配布一覧・レビュー記録は自動更新せず、個人データや他の `work` の内容には触れません。

```sh
python -B -X utf8 web/scripts/audit-git.py
node web/scripts/build-offline.cjs
python -B -X utf8 web/scripts/prepare-release.py
python -B -X utf8 work/release/web/scripts/audit-content.py --record
```

生成された `work/release/web/RELEASE_CONTENT.json` を `web/RELEASE_CONTENT.json` へコピーします。
変更した依存物・素材・通信・テスト結果をレビューし、`RELEASE_REVIEW.json` の対象ハッシュと根拠を更新します。
`--record` はファイル一覧とハッシュの記録だけで、権利や公開可否を認定しません。続いて：

```sh

node work/release/web/scripts/check-release.cjs
```

GitHub CIとPages公開ワークフローはそれぞれ同じコミットからZIPを生成し、既存の配布一覧・確認記録を検査します。
配布一覧・確認記録・翻訳・オフラインマニフェストはCIや公開時には再生成しません。

開発サーバーでもZIPのダウンロードを試す場合は、ルートで `python -B -X utf8 web/scripts/package_source.py` を実行します。
このローカル生成物もGitでは無視され、公開時には使い回しません。

Node.js 24、Python 3.12以上、Playwright 1.62.1と対象ブラウザを使用しています。
Playwrightは開発用の依存物で、アプリの配布物へ含めません。Windows CIはEdgeとPC版WebKitを使用します。
リポジトリのルートから通信の固定テスト依存物を用意してから実行します。

```sh
python -B -X utf8 web/scripts/prepare-link-tests.py
```

開発サーバー起動後に次を実行します。

```sh
node web/scripts/test-all.cjs
node web/scripts/test-all.cjs --webkit
```

結果は無視対象の `web/test-results/suite-*` に保存します。一件でも失敗すると非ゼロ終了します。

## 画面消灯防止と動作の計測

「設定 → 一般 → プレイ中は画面を消灯しない」は初期状態でオンです。対応APIがない端末やOSが許可しない状態では通常どおり動作します。ゲームの一時停止・終了・バックグラウンド移行で解除します。

「設定 → 診断と動作の計測」の計測は初期状態でオフです。オンにしてプレイし、再度診断画面を開くと描画間隔・描画処理・音声供給の遅れ・保存処理の集計を確認できます。直近最大256件の時間値と回数だけをこのタブ内に保持し、診断書き出しにも含めます。ゲームや測定条件を切り替えて比較する場合は計測結果を消去してください。コアの処理FPSと画面の表示間隔は異なります。

診断書き出しの`performance.audio`には、音声キューの最大先行時間、超過による破棄回数・サンプルフレーム数・音程維持処理のリセット回数も含みます。計測をオンにしたプレイ中だけ集計し、音声そのものは記録しません。再生速度や音量を自動補正する機能ではありません。

## 通信先の設定

オンライン通信の「中継サーバー」で、対応する別のWSSサーバーを選べます。相手も同じ接続先を選ぶ必要があります。通信を始めるまで接続せず、通信中は変更できません。接続先はこのブラウザにだけ保存し、バックアップへは含めません。サーバーにはゲーム通信データとIPアドレスが伝わるため、信頼できる接続先を利用してください。

## 参照元の更新確認

参照元の更新は[更新検出の手順](scripts/upstream-README.md)に従い、GitHub Actionsで毎日メタデータを比較します。mGBAは独自パッチを維持してビルドし、権利・依存物・保存互換性と全CIを通過した候補を自動採用・公開します。その他の参照元は検出のみです。セーブ変換ツールは現時点で公開配布フィードがないため自動取得せず、提供物を受け取って既存の差し替え検査を実施します。

### 起動できないセーブを復旧する

ゲーム詳細の「ゲーム内セーブ・保存履歴」は、ROMを起動する前にも開けます。現在のセーブのハッシュ不一致で起動を止めた場合も、この画面を表示します。最近の保存、5分ごとの履歴、手動・自動ステートに付属するゲーム内セーブから、整合性を確認できたものだけを復元できます。

復元前のセーブは破損していてもそのまま端末内に退避し、置換と同じトランザクションで記録します。容量不足や他タブのプレイ中は置換しません。「現在のセーブをそのまま書き出す」「退避した元データ」からの書き出しは修復を行わない原本です。ゲーム側の内容の正常性まで保証する検査ではありません。

メニューを開いた際にもゲーム内セーブを端末へ記録します。終了時の保存に失敗した場合はプレイ中のデータを残し、保存後の終了処理だけに失敗した場合は「終了」から再試行します。OSによる即時終了や端末故障に備え、別ファイルへのバックアップも残してください。

### 起動時のコア・音声とバックアップのエラー

コアの取得・初期化に失敗した場合は、ゲームを終了した状態で「再読み込み」と「アプリの更新」を案内します。通信切断と配布ファイルの版違いは画面側で断定できないため、まず接続を確認してください。セーブの破損や形式の不一致は別の復旧案内で扱います。

「プレイ」の操作時に音声を準備し、読み込み後も同じ音声出力を使います。ブラウザが音声開始を許可しない場合は、プレイ画面の「音を有効にする」を押してください。一時停止・終了中には表示しません。ゲーム中のゲームパッド取得はゲーム側に任せ、メニュー側は操作を受け付ける間だけ取得します。

バックアップの検証失敗では、特定できる場合に対象ゲーム名と識別子を表示します。同名のゲームは識別子で区別できます。破損した記録を黙って除外せず、元データを保持したまま停止します。ゲーム名・識別子はこのエラー画面にだけ追加し、診断レポートには記録しません。

### 大容量ROMの読み込みと128 MiBへの準備

現在のGBA上限は64 MiBです。`src/core/rom-capacity.js`に、機種・コアの受け入れ容量と、ZIP・パッチの作業容量を分けて管理しています。`futureGBAROMBytes`は将来の検証対象であり、128 MiBの受け入れには使いません。UI、直接の取り込み、Worker、ZIP展開、コア起動で未対応容量を拒否します。セーブの保存先、コアID、セーブ容量とステート互換IDは変更していません。

新しく追加・更新する32 MiB超のGBAはBlobで保存し、mGBAへ4 MiBずつ転送します。Blob保存で既知のUnknownErrorが発生するWebKitは、原子的に失敗した後に従来の配列保存へ戻します。容量不足など他のエラーでは再試行しません。以前から保存している配列ROMも読めます。既存ROMを自動で書き換える処理はありません。取り込みのハッシュ計算・ROM識別では全量読み込みが残るため、アプリ全体の使用メモリが4 MiBになる意味ではありません。

128 MiBを有効にするには、対応する上流コアのバンク切り替え・マッピング仕様を確認して再ビルドし、対応ソースとライセンス記録も更新します。現在の同梱ソースは32/64 MiBの分岐を持つため、JavaScriptやbridgeの上限値だけを変更してはいけません。64 MiB以降の読み出し・ROM終端・CPU速度判定・拡張セーブ検出・旧ステートと通信を合成ROMで確認し、iPhone実機の起動/終了/再起動も測定してから容量を変更します。WASMの上限、パッチの同時保持量、ZIPの展開上限はそれぞれ別に見直してください。
